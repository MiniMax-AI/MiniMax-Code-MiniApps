# 道闸运维知识助手

面向道闸 / 道闸售后运维团队的本地模型运维控制台。

把你自己的手册、规则文件和合同投喂进来，它会建成本地可检索的知识库；提问时给出**带来源的标准
答案与解析、置信度和命中的原文片段**；用自然语言要求改代码时，给出可审阅的 `SEARCH`/`REPLACE`
补丁与 unified diff——写盘前自动备份，任何一次改动都能在同一个面板回滚。

凡是需要理解、判断或生成的地方，都调用真实模型：没有写死的回复，没有关键词匹配，没有固定评分。
模型返回什么，页面就渲染什么。

## 功能

| 面板 | 作用 |
| --- | --- |
| 知识库 | 投喂 `.txt`、`.md`、`.docx`、`.xlsx`、`.pdf`，标注分类（知识点 / 规则 / 合同 / 其他），由模型生成标题、摘要与要点，切分成片段后用 `bge-m3` 建立索引。 |
| 运维问答 | 对问题做向量检索，取回相关度最高的片段，再由模型产出标准答案、解析、置信度与资料未覆盖的部分，并列出全部来源及分数。 |
| AI 改代码 | 定位要改的区域，由模型产出 `SEARCH`/`REPLACE` 补丁块，要求每个 `SEARCH` 在原文中**唯一匹配**，写入前先展示 unified diff。超过 12000 字符的大文件走「模型定位区域 → 在窗口内生成补丁」两阶段。 |
| 部署 | 执行设置里已保存的部署命令，工作目录必须位于允许写入的目录之下，并保留退出码、标准输出与错误输出。 |
| 路由与设置 | 切换路由模式，维护允许写入的目录、资料目录、备份根目录与部署命令。 |

## 模型路由

四种模式在**路由与设置**里切换：

| 模式 | 行为 |
| --- | --- |
| `auto` | 按请求体量与本地模型上下文窗口逐次决策。超出本地窗口先走在线模型、失败再降级回本地；否则先走本地、失败降级到在线。 |
| `local_first` | 始终先调用本地模型，本地失败降级到在线模型。 |
| `local_only` | 只调用本地模型，不做任何在线降级。 |
| `online_only` | 只调用在线模型，不做任何本地降级。 |

降级是双向的，且每次都会说明：答案与补丁都会显示「请求的路由 / 实际使用的路由 / 实际使用的模型 /
原因」。`local_only` 与 `online_only` 不降级。

本地模型来自 [Ollama](https://ollama.com)，默认 `http://127.0.0.1:11434`（地址可改）。优先选择名称以
`qwen3:14b` 开头的对话模型，否则取参数量最大的可用对话模型，再退回第一个。上下文窗口按模型规模固定：
**14B 级 8192 token，更小的模型 16384 token。**

嵌入模型固定使用 `bge-m3`，且不参与路由——检索质量不随回答问题的聊天模型变化。

「在线」路由走宿主的 Agent 通道（`context.agent`），每次只取一次受限的 JSON 回复，该回合本身没有文件、
工具与网络权限。

## 安装与打开

1. 在 MiniMax Code 中安装本插件包。
2. 启动 [Ollama](https://ollama.com) 并拉取所需模型：
   ```bash
   ollama pull qwen3:14b
   ollama pull bge-m3
   ```
3. 打开应用，进入**路由与设置**：
   - **允许写入的目录**——AI 改代码只能写这些根目录，越界会被明确拒绝。
   - **资料目录**——允许浏览与投喂的根目录。
   - **备份根目录**——备份写入位置。每次应用补丁都会新建 `<备份根目录>/<时间戳>/`，内含原文备份、
     把备份文件名映射回原路径的 `manifest.json`，以及记录补丁与哈希的 `record.json`。
   - **部署命令**——部署面板允许执行的命令。
4. 选择路由模式，开始投喂资料。

面板标题保持中文，这是产品原本的语言；README、插件清单与代码注释使用英文。

## 备份与回滚

应用补丁不会静默覆盖文件：

1. 原文复制到备份根目录下新建的时间戳目录。
2. `manifest.json` 记录 `<备份文件名>` → `<原文件绝对路径>`。
3. `record.json` 记录补丁、unified diff、改动前后的 SHA-256 与状态。
4. 新内容以原子方式写盘。

**AI 改代码**面板列出所有已记录的操作，**回滚**会从备份还原文件并校验哈希。早前工具用同一套
`manifest.json` 格式留下的备份同样会被列出，也可以回滚。

## 安全边界

- 写入被限制在配置的允许目录内，校验使用真实路径，符号链接无法越界。
- 只有可编辑扩展名白名单里的文本文件能被改写。
- 只有当每个 `SEARCH` 块在当前文件中**唯一匹配**时补丁才会落盘；匹配不唯一或已过期都会拒绝，并让模型重做。
- 部署面板只能执行设置里已保存的命令，没有单次请求的自由文本命令入口；每条命令的工作目录必须位于允许写入的目录内。
- 密钥不会进入页面：页面只通过受限业务路由与 Node 服务通信，浏览器里不发生任何模型调用。

## 测试环境

- MiniMax Code 3.1.19，Windows 11（build 26300）。
- 插件声明了 `agentAccess: ["session.run"]` 与 `surface.window`，因此需要 **MiniMax Code 3.1.2 或更高版本**。
- 已在应用内浏览器完成客户端验收：投喂 `.txt` 运维手册（模型摘要、`bge-m3` 索引、1 个片段）、询问质保期
  问题（标准答案、解析、置信度、引用来源及其相关度、路由决策）、补丁预览（`SEARCH` 唯一匹配与正确的
  unified diff）、应用补丁（备份目录含 `manifest.json`、前后 SHA-256）、回滚（文件还原、状态更新）、执行
  部署命令（捕获退出码与输出）、切换路由模式（落盘并还原）、越界写入被拒。控制台无报错、无失败请求。
- Node 侧测试套件另外覆盖了 `.docx`、`.xlsx`、`.pdf`（ASCII 与通过 `ToUnicode` 的中文）、GBK 编码文本与损坏
  文件，全部基于真实本地 Ollama。

## 数据与权限

- **读取的文件**——页面中上传的文件（`.txt`、`.md`、`.docx`、`.xlsx`、`.pdf`）、在资料目录下浏览的文件，
  以及补丁请求的目标源文件（必须位于允许写入的目录内）。
- **写入的文件**——被改动的目标文件；备份根目录下的备份副本、`manifest.json` 与 `record.json`；以及应用
  自身的状态文件（见下）。
- **网络主机**——本地 Ollama 服务 `http://127.0.0.1:11434`（地址可改），使用 `/api/tags`、`/api/chat`、
  `/api/embed`。本插件包不发起其他出站请求。
- **派生进程**——用户在设置中保存的部署命令，以 `shell: true` 在配置的工作目录中启动；Windows 上应用销毁
  时用 `taskkill` 结束整个进程树。
- **Agent 回合**——`context.agent.run` 用于「在线」路由，每次请求一个受限的 JSON 回复，该回合不获得文件、
  工具或网络权限。
- **读取的会话**——无。未声明 `session.read`，从不列出或观察用户会话。
- **调用的工具**——无。未声明 `toolAccess`，从不调用 Connector 或 MCP 工具。
- **麦克风 / 摄像头 / 通知**——无。未声明 `deviceAccess`，页面不申请任何浏览器权限。
- **读取宿主导航**——无。未声明 `hostAccess`；页面只跟随宿主明暗主题，该能力无需授权。
- **状态存放位置**——宿主的私有 `context.dataDir`：`kb/` 存放投喂的片段、向量与文档记录，`patches/` 存放待应用
  的补丁，`settings.json` 存放路由模式、各目录与部署命令，`deploy-logs.json` 存放部署日志。页面只在
  `localStorage` 保存当前视图状态。插件不读取任何宿主文件，也不读取 `context.dataDir` 之外的运行时状态。
