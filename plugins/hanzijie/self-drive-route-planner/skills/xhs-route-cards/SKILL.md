# 自驾行程 → 小红书路线卡片

把当前已规划路线变成一组**小红书手帐贴纸风**的图片卡片。默认产物:

1. 1 张首图:路线编号点线示意 + 按天速览 + 里程/费用钩子;
2. 每天 1 张行程图:当天站点流 + 看点(带具体名词)+ Tips;
3. 一份 Markdown:嵌入图片、每页可见文案、假设说明。

图片比例固定 **3:4 竖版**。所有成图交付前**必须**用本 skill 的贴标脚本在右下角加 MiniMax 小标(代码后处理,见 Step 6),没贴标的图不得交付。

## 触发与边界

仅在用户要求把已有自驾行程做成小红书攻略图、路线图、旅行卡片、行程海报时使用。

- 只读行程 → 视觉内容,不修改行程任何数据;
- 没有活动行程时提示先用 `route-planning` 规划,不自动创建;
- 不凭空补景点、餐厅、价格、天气、结论;所有活动事实只来自站点 `note`;
- 生成图是**路线示意,非导航地图**,Markdown 必须标注;
- 生成图片消耗 MiniMax 图片额度。首次生成前确认一次页数与额度;用户已明确表达重做/继续意图时不再重复确认。

## Step 1:读取并锁定行程快照

调用 `trip_get`(省略 `trip_id` 读当前活动行程),记录 `trip_id`、`revision`、完整 `trip` 对象,后续只用这份快照。

检查:`origin`/`destination` 存在、`waypoints` 非空、`route_status` 就绪、`selected_route_id` 可在 `route_options` 中找到。路线选择:优先已选路线;未选则用第一候选并在 Markdown 注明;`route_options` 为空或状态未就绪时不自动重算,先告知用户。遇 `REVISION_CONFLICT` 重新 `trip_get`,丢弃旧快照。

## Step 2:备注语义解析(核心,不是截断)

`note` 是活动内容唯一来源,但必须**理解语义后重组**,严禁机械截断丢信息。

对每条 `note` 按语义拆分类:

| 类别 | 例子 | 去处 |
|---|---|---|
| 看点/玩法 | 熊猫馆(奥运/韵韵)、崖壁蜂箱、野人洞、金猴岭 | 当天"看点"条目 |
| 游玩时长 | 游 2-2.5h、打卡 30-40min | 跟在对应看点后 |
| 价格/门票 | 摆渡车 ¥70/人(含小火车) | 看点或 Tips,数字必须原样 |
| 时间窗 | 晨雾 06:30-08:30、晚霞 17:30-18:30、早 08:30 出发 | 站点流或看点 |
| 交通/接驳 | 私家车不可入必乘摆渡、G42 出口、40min 夜路 | Tips |
| 餐饮 | 野菜/野香菇/腊猪蹄、土家腊肉/懒豆腐/合渣 | **所属站点**当天的条目 |
| 住宿 | Day 1 晚住宿、第3晚住坪迁 | 当天站点流尾部"宿 X" |
| 海拔/气温/装备 | 海拔1200m、夜温10°C 带薄羽绒 | Tips |
| 预警 | 雾大能见度差提前看天气、国庆或管制、赶时间可跳 | Tips,优先级最高 |

硬规则:

- **具体名词必须保留**:动物名、菜名、景点小地名、价格、海拔、时间窗。这些是小红书笔记的信息价值所在,压缩时删修饰词、保名词数字;
- **信息归属铁律**:每条信息只能出现在它所属的站点与日期。反例(真实事故):把松柏镇备注里的"合渣"写成 Day 5 早茶——禁止;
- 备注为空写"活动待补充",不虚构;
- 隐私、长 token、内部链接不进图。

按天分组:优先 `depart_at`(Asia/Shanghai);备注中的 `Day N` 标记辅助;两者都没有时全部归第 1 天并在 Markdown 说明。同一 POI 出现两次(去/返)合并叙述,不重复占页。

## Step 3:页面脚本

先产出 Markdown 页面脚本供审阅,再生成图片。

**文案必须是完整句子,不是名词电报**。每条看点写成"动词 + 对象 + 关键信息"的攻略句,读者看完知道到了那里**先干嘛、再干嘛、要花多少钱/多久**。反例(太简略,真实退稿):"神农顶3106m 金猴岭·神农谷·板壁岩 4h";正例:"登华中屋脊神农顶3106m 沿线停金猴岭·神农谷·板壁岩 玩约4h"。名词串只允许出现在首图的按天速览和菜名列举里。

每页可见文字预算 **180-300 字符**(含标题),信息完整优先于极简;超预算时先删修饰词,再合并同类项,最后才删次要看点。

### 首图结构(速览页,允许短语)

```
{行程名或"目的地+N天N晚"}
{日期范围}|{起点}出发 {终点}收官
D1 {当天极简摘要}
D2 {当天极简摘要}
...
全程{里程}|{费用钩子}
路线示意|非导航地图
```

### 日页结构(攻略页,必须完整句)

```
Day {n}|{月.日} {当天主题}
{站点流:A 时刻出发→B→C 宿D}
• {完整句:先看什么再逛什么 约Xh}
• {完整句:交通/换乘怎么走 多少钱}
• {完整句:什么时间窗该在哪干嘛}
Tips {预警/装备完整句,1-2条}
```

- 每页至少一个真实站点名;主题词从当天事实提炼(如"华中屋脊日"),不发明事实;
- 文案中不用 emoji 字符(图标由插画表达);用 `→` `·` `|` `•` 做结构符号。

## Step 4:视觉规格(小红书手帐贴纸风)

所有 prompt 用中文书写,并固定包含:

- 竖版 3:4,奶油白/暖白背景(非冷白),四周留白;
- **小红书旅行攻略手帐风**:超大号黑色粗体中文标题,标题关键词用荧光色块高亮(马克笔划重点效果);
- 圆角卡片分区、虚线路线连接彩色编号圆点、日期徽章、位置图钉;
- 手绘扁平风小插画点缀:山峰、云朵、小汽车、湖泊、杉树、温泉雾气等,贴纸感,克制不堆砌;
- 多巴胺亮色每页 2-3 种:珊瑚橙、柠檬黄、薄荷绿、天蓝、薰衣草紫;
- 正文深灰/黑粗体无衬线,高对比,手机缩略图可读;
- 首图:竖向路线点线图为主视觉,编号圆点 + 站名;日页:时间轴/站点流 + 看点卡片;
- 禁:真实照片、写实伪地图、二维码、水印、任何 logo(标识由代码后贴)、英文占位文字、乱码微缩字;
- **右下角必须留白**:页面右下角(约图宽 12% × 图高 8% 的区域)不放任何文字和重要元素,给代码后贴的 AI 标记预留位置,prompt 中明确写入这一要求;
- 图中中文必须与页面脚本逐字一致。

### Prompt 模板

```
小红书旅行攻略手帐贴纸风竖版海报,比例3:4。奶油白背景,大量留白。
超大号黑色粗体中文标题,关键词用{高亮色}荧光色块高亮,马克笔划重点效果。
{页面角色:首图=竖向路线点线图,编号彩色圆点+站名+虚线连接 / 日页=日期徽章+站点流一行+圆角看点卡片+Tips色块}。
手绘扁平风小插画点缀:{山峰/云朵/小汽车/湖泊/杉树,按当天内容选2-3个},贴纸感。
多巴胺配色:{2-3色}。正文深灰粗体,手机缩略图可读。
画面中的中文必须与下方文案逐字一致,不得增删改字:
"""
{页面文案}
"""
禁止:真实照片、写实地图、二维码、水印、logo、英文、乱码、虚构小字。
```

## Step 5:生成图片(可批量)

1. 使用本机注册的 `generate_image`(MiniMax Code Connector 工具,如 `connector__matrix__generate_image`),先读当前 schema,参数以 schema 为准;
2. schema 的 `requests` 为数组时**优先一次批量提交全部页面**,每个 request 固定 `aspect_ratio: "3:4"`,并用 `output_file` 命名(`xhs_01_cover` / `xhs_02_day1` / …)以对齐页码;`failed_items` 单独重试,不重发成功页;
3. 分辨率选 1K(需要更清晰可 2K);
4. 生成后用 `get_asset_url` 取 URL 下载到本地工作目录,文件名与页码对应;
5. 文字校验:用 `describe_images` 抽查首图 + 信息最密的一页;OSS 直链读不了时先 `upload_temp_url` 再校验;发现错字/乱码/顺序错乱只重做该页;
6. 不在 prompt 或日志中暴露任何 Key/token。

## Step 6:贴 AI 生成小标(必做,代码实现)

交付前对**每张**成图执行贴标脚本,在右下角加 MiniMax 小标:

```bash
python3 {本 SKILL.md 所在目录}/scripts/add_ai_badge.py 图1.jpg 图2.jpg ...
```

- 脚本与素材随本 skill 分发,位于 **SKILL.md 同目录**下:`scripts/add_ai_badge.py`、`assets/minimax-logo.png`;以 skill 实际加载位置解析路径,不要写死机器相关的绝对路径;
- 默认参数已调好:badge 宽=图宽 8%、边距 2.5%、白底自动转透明、不透明度 0.9、原地覆盖;一般不需要改;
- 依赖 Pillow(`python3 -c "import PIL"` 验证);
- 这是代码后处理,**不得**把 logo 写进图片生成 prompt;
- 贴标后抽查一个角落裁片确认成功;未贴标的图不得进入交付。

## Step 7:校验与 Markdown 交付

- 校验:比例≈3:4、页数页序与脚本一致、文字无乱码错字、已贴标;
- 失败页标"未完成"并给原因,不静默重试付费任务;
- 交付结构:

```markdown
# {行程名}|小红书路线卡片

> 共 {n} 页|竖版 3:4|路线示意,非导航地图|右下角 MiniMax 标=AI 生成

## 图片
### 1. 路线总览
![](已验证路径)
### 2. Day 1|{主题}
![](已验证路径)

## 页面文案
- 首图:{可见文案}
- Day 1:{可见文案}

## 说明
- 活动与贴士全部来自行程站点备注;未填写的没有补写。
- {假设:未选候选路线/无逐日时间等}
```

## 失败处理

- `NO_ACTIVE_TRIP` / 缺起终点 / 路线未就绪:提示先完成规划,不猜数据;
- `generate_image` 未注入或 schema 不支持 3:4:停止付费生成,只交付页面脚本;
- 贴标脚本失败(Pillow 缺失等):先修环境再交付;实在不行交付未贴标图并**显著声明**缺 AI 标识,让用户决定;
- 用户在生成前改了行程:重新 `trip_get`,重出脚本,不沿用旧文案。
