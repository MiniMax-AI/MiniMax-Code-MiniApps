# MiniMax Bot Bridge

[English](README.md) | 简体中文

把你的手机和桌面上的 **MiniMax Bot** 团队配对起来。Bridge 是运行在桌面端的 Mini App：它显示配对码、
保存已配对的手机，并通过你自己运营的中继，把团队的对话和工具活动转发给手机客户端。

这是一个独立项目，不是 MiniMax 官方应用。它不修改、也不复刻官方 MiniMax Bot 插件——它调用 Host 已经
暴露的团队工具，桌面端始终掌握主导权。

## 它能做什么

- **配对界面。** 申请一个一次性的六位配对码，在桌面上读出来，并查看或撤销与这台桌面配对的手机。
- **中继配置。** 设置中继地址、账号 ID、桥接 ID、桥接凭据和显示名称。配置变化后桥接会自动重连；
  它拒绝使用自己不该连接的中继地址。
- **团队访问。** 通过 Host 暴露的 `minimax-bot` 工具读取团队成员资料、群组成员和对话历史，并以某个 Bot
  的身份发送消息。
- **托管回合。** Bot 的回合可以运行在桥接自己拥有的会话里，而不是团队自己的对话中，并带有流式输出和
  桌面的权限提示。

手机端是另一个应用：[MiniMax Bot Mobile](https://github.com/nattiini45/minimax-bot-mobile)，
一个面向 Android、iOS 和网页的 Expo / React Native 客户端。没有它，桥接没有意义；而除了中继之外，
它也不需要别的组件。

## 运行要求

- MiniMax Code 3.1.5 或更高版本——见[环境与兼容](#环境与兼容)。
- 同一台桌面上装有官方 **MiniMax Bot** 插件。桥接通过 Host 的工具 API 调用该插件的工具。没有它，
  桥接仍然可以启动、配对并报告诊断信息，但无法展示或驱动你的团队。
- 你自己运营的中继，以及为它签发的桥接凭据。线路流程见[配对与凭据](docs/PAIRING.md)，
  中继 Worker 和签发命令见手机端仓库。

## 安装

把整个插件目录（包含隐藏的 `.minimax-plugin` 目录）复制到客户端的 `plugins` 目录：

```text
仓库路径：plugins/nattiini45/minimax-bot-bridge/
安装到：  <dataDir>/plugins/minimax-bot-bridge/
清单文件：<dataDir>/plugins/minimax-bot-bridge/.minimax-plugin/plugin.json
```

`dataDir` 默认是用户主目录下的 `.minimax` 目录（`~/.minimax`）。作者目录（`nattiini45/`）只是在仓库里
归类贡献者，安装后的插件 ID 是 `minimax-bot-bridge`。重启 MiniMax Code，确认插件已被识别并启用，然后
让 Agent 打开「MiniMax Bot Bridge」。

更新时，先关闭应用并退出 MiniMax Code，再整体替换插件目录；备份请放在 `plugins/` 之外。桥接自己的状态
保存在 Host 的数据目录里，不在插件目录里，所以替换目录不会丢状态。

## 配置与配对

1. 打开桥接界面。
2. 填入中继地址（`wss://…` 或 `https://…`）、账号 ID、桥接 ID，以及用中继密钥签发的桥接令牌。
3. 申请配对码，把这六位数字念出来。
4. 在手机端填入同样的中继地址、同样的账号 ID 和这六位数字。

配对码一次性使用，五分钟后过期。手机随时可以在桥接界面上撤销。

界面目前为英文。

## 环境与兼容

- MiniMax Code 3.1.10，Windows 11（x64），并安装了官方 MiniMax Bot 插件。
- Node.js 24.22.1 与 npm 11.19.1。
- 桥接自带测试在该机器上全部通过：在插件目录里执行 `npm test`。不需要安装依赖，也不需要网络。

## 数据与能力边界

| | |
| --- | --- |
| **写入的文件** | 仅限 Host 的私有数据目录（`context.dataDir`）：`bridge-config.json`（中继地址、账号 ID、桥接 ID、显示名称、每个 Bot 的回合模式）、`bridge-token`（中继凭据，仅所有者可读）和 `ledger.json`（回合、工具与权限记录——计数与标识，不含消息正文）。每个房间另有 `rooms/<hash>/ledger.json`。 |
| **读取的文件** | 启动时只读上面这几个文件。没有别的：不读 Host 文件，不读其他插件的文件，不读用户文档。 |
| **网络** | 只访问你配置的中继地址，且只走 HTTPS 或 WSS。明文的 `http://`／`ws://` 地址只接受回环地址。`wss://` 和 `https://` 指的是同一个中继，凭据不会在两者之间传递。 |
| **启动的进程** | 没有。桥接是一个 Node 进程，不派生任何子进程。 |
| **Agent 回合** | 有——`agentAccess: ["session.run"]`。桥接通过 Host Agent 在自己拥有的会话里运行 Bot 回合，并向它索取模型。它从不读取你的其他对话：没有声明 `session.read`，它展示的团队对话历史来自团队工具。 |
| **调用的工具** | 有——`toolAccess: ["call"]`。桥接调用 Host 暴露的 `minimax-bot` 团队工具（`mcp__minimax-bot__…`），用来读取团队、群组和对话历史，并发送消息。每次调用都按你的权限规则判定。 |
| **麦克风** | 不使用。桥接不录音，也不做语音转写。 |
| **状态存放位置** | Host 的私有数据目录，位置由 Host 管理且不透明。除此之外不写任何文件。中继的状态保存在中继运营方那边。 |

### 安全说明

- **桌面端是信任边界。** 桥接只监听回环地址，并在回答可能改变配置的请求前校验调用方自身的请求头和一个
  每进程生成的密钥。这保护的是本地网页界面，并不能隔离同一台机器上的其他原生进程。
- **配对成功就等于授予了桌面访问权。** 已配对的设备可以行使桥接提供的能力。只把配对码告诉你要授权的人，
  并撤销不再使用的设备。
- **信任你的中继。** TLS 保护的是每一段连接，但中继转发的 JSON 没有端到端加密。中继运营方可以读到对话和
  操作负载。
- **能力是被授予的，不是被复刻的。** 桥接只使用那台桌面上的 Host 与团队工具所提供的能力。它自己不持有
  MiniMax 账号凭据，用的是桌面端已有的账号和授权。

## 开发

```sh
npm test
```

测试基于 Node 内置的测试运行器，不需要依赖，也不需要网络。运行时负载是自包含的：只用 Node 标准库，
共享协议已经内置在 `miniapp/node/protocol/`。
