# GML 练习记录 · 项目存档管理器

这是 MiniMax Code 的一个 Mini App：多本互不干扰的 GML 学习笔记，每本都能独立打卡、登记 API 库、记录代码载体。数据存在 Mini App 的数据目录里（`GML-Saves/`，另有 `GML-Trash/` 回收站与 `exports/` 导出目录）。

Agent 通过托管 MCP server `gml-notes` 访问这些数据。

## 什么时候用

- 用户问「我的 GML 练习记录有哪些」「上次那道云层特效怎么写的」
- 用户要在这台机器上搜索某段 GML 代码、某个 API 名字
- 用户要复用已经登记过的 GML 函数或内置变量
- 用户要新建一本练习笔记，或把存档导出备份

## 可用工具

| 工具 | 用途 | 关键参数 |
| --- | --- | --- |
| `list_projects` | 列出全部练习笔记，含记录数、API 数、打卡天数、存档文件名 | 无 |
| `get_project` | 读一本笔记的完整内容：练习记录、API 库、打卡日历、设置 | `project`（项目 ID 或名称） |
| `search_notes` | 跨所有笔记搜索记录名称、题目要求、提示、代码文本、API 介绍 | `query`、`limit`（默认 20） |
| `list_api_library` | 汇总 API 库（代码名、介绍、参数、被哪些笔记引用） | `project`（可选，不过滤时汇总全部） |
| `create_project` | 新建一本空白练习笔记 | `name` |
| `export_backup` | 把全部笔记（含回收站）导出成 JSON 备份，落在 `exports/` | 无 |

推荐顺序：先用 `list_projects` 拿到项目 ID 与名称，再用 `get_project` 或 `search_notes` 取内容。

## 记录里有什么

一条练习记录包含：

- `name` — 记录标题（用户一般写成「082.云层特效」这样的序号 + 主题）
- `requirement` — 题目要求
- `hint` — 提示
- `modules` — 代码载体，按顺序排列，常见三类：
  - **操作描述**：这一步在编辑器里做了什么（纯文字）
  - **脚本**：GML 代码，第一行写 `// 文件名` 标明来源文件
  - **对象**：带预定义变量表和事件代码框（Create / Step / Draw 等）
- `apis` — 这条记录引用了哪些 API（引用式：API 库只存一份，记录只存引用）

API 库条目：`code`（函数名或内置变量名，只写名字）、`desc`（一句话说明）、`params`（参数列表）。

## 边界：Agent 能读，不能直接改记录内容

记录正文（题目、提示、代码载体）只能在 Mini App 页面里编辑——那是浏览器侧的写入通道，托管 MCP 不暴露。所以：

- **不要**试图用 MCP 工具写入或覆盖已有记录内容，会失败。
- 用户说「把这段代码记进我的笔记」时，正确做法是：把整理好的内容（标题、题目要求、提示、按顺序排好的脚本/对象载体）直接给用户，告诉他粘到页面里对应位置。
- 用户说「建一本新的」时，用 `create_project`，这个是支持的。

## 写作约定（整理给用户的内容时遵守）

- 代码逐字贴，不改一个字；需要改的地方写在提示里，不要动代码本身。
- 脚本载体的第一行写 `// 文件名`。
- 对象载体用「预定义变量表 + 事件代码框」两部分表达。
- API 只登记代码名；一条记录里引用 API 时，说明它引用的 API 名字列表。

## 数据与隐私

所有练习数据只写在本机 Mini App 数据目录，不上传任何服务器。唯一的网络访问是用户在页面里主动点「抓取最新版本」时去下载打卡网页版（默认来源 `https://basetier-gml.github.io/gml-practice-log/`）。
