# 灵签易占 (`chinese-divination`)

[English](README.md) | 简体中文

中国传统文化占卜 Mini App。以梅花易数起卦，按体用生克断吉凶，内置六十四卦全文与干支历法。
全部计算在本机完成：不联网；包目录以外只读一个文件——Host 为它建的那个私有 `dataDir` 里的卦历。

界面为中文。想直接上手，看下面的**使用指南**；想看推演口径与能力披露，往下翻。

## 使用指南

### 三十秒上手

安装后对 MiniMax Code 说「打开灵签易占」。页面开在四个分区：**起卦 / 卦库 / 历法 / 卦历**。

想在对话里直接起卦，不用开页面，说一句「帮我起一卦」就行，见下面的[在对话里起卦](#在对话里起卦)。

### 怎么问才对

**第一行是重点。** 上面那个「所问何事」输入框决定了你这次问的是哪一类事，它会改变断语的侧重：

| 你写 | 认出的事类 | 应期会指向 |
| --- | --- | --- |
| 下个月这份 offer 该不该接 | 事业功名 | 巳午（相辰戌丑未） |
| 这笔投资还能不能赚 | 财运 | 申酉（相亥子丑） |
| 他会不会主动来找我 | 感情 | 亥子（相寅卯） |
| 明年春天结婚日子好不好 | 婚恋 | 寅卯（相巳午） |
| 父亲的手术要不要等 | 疾病 | 辰戌丑未（相申酉） |
| 这套房该不该买 | 房产车契 | 辰戌丑未（相申酉） |
| 下周的考试能过吗 | 学业文书 | 寅卯（相巳午） |

写具体比写「我的运势好不好」有用得多——**前者能认出事类、算出应期，后者只能退回按用卦推**。
如果你写的事实在认不出（比如「今天天气怎么样」），应用不会瞎套一个五行，会在断语里明说「未落到已知事类，
应期按用卦推」。**「没写问题」与「写了但这张表没接住」是两回事，断语分开说**：后者会把九类事类
列出来告诉你是哪一层缺了，不会说成你没写。

**问事不影响吉凶。** 同一个卦，问财和问婚，「凶」不会翻面——吉凶由卦自己的体用生克与月令旺衰决定。
变的是应期落在哪几个月日、哪条断语更值得看，以及结果页顶部那句「问的是事业功名，卦里说的就是
这份前程」——换个问法换的是这句话的取象，不是吉凶。这一点是刻意的：占卜可以帮你把问题想清楚，
但不该由你写什么问题来买到一个好答案。

这句要认得出事类才说得上。上面那九类之外的事，应用宁可整句不摆，也不拿一句听着像的话来凑。

### 四种起法怎么选

| 你的处境 | 用哪个 | 会变卦的频率 |
| --- | --- | --- |
| 心里有个「现在到底怎么样」的疑问 | **时间起卦** | 每时辰一换（两小时） |
| 只想知道今天整体如何 | **每日一卦** | 一天一换 |
| 已经想好要问什么，想自己定个数 | **数字起卦** | 换一组数字就变 |
| 要一个跟当下完全无关的、随机的卦 | **铜钱摇卦** | 每掷一次都不同 |

前两种是**按时间取数**的，所以同一个时辰/同一天内反复起卦，必然是同一个卦——这不是程序在复读。
应用在结果卡上会写明自己的节律：当前取数依据、下一次何时变，甚至会直接告诉你「到丑时再起，将得
风山渐」。你可以看着它转。想每次都不一样，用铜钱摇卦或数字起卦。

### 数字起卦怎么用

1. 点「数字起卦」，输入框会展开。
2. 静心默念你问的事，**心里想出两个数**（不必真的想，顺手取也行）。
3. 填进去，点「起卦」。第一个数取上卦，第二个取下卦，两数之和取动爻。
4. 起完输入框会自动清空，免得你连点两次看到同一个结果而以为它写死了。

「随手取数」按钮会替你随机取两个 1–99 的数，适合你就是想快速来一卦的时候。

### 铜钱摇卦怎么用

点「铜钱摇卦」展开摇卦区，点「掷钱」六次，自初爻向上。按钮上方有一条进度条与「已摇 n / 6 爻」的
计数，每掷一爻跟着走一格，剩几爻不用自己数。界面会逐爻显示阴阳与老阴老阳，六爻掷完
后点「成卦解卦」。想重来点「重来」。这是四种起法里唯一每次都不同的。

### 结果页怎么看

| 位置 | 内容 |
| --- | --- |
| 卦题 | 写了所问就显示所问，没写就按起法命名（今日之卦 / 此刻之卦 / 心中之卦 / 手掷之卦） |
| 结论块 | 整块占满版心，挂在卦题正下方、**两栏之上**——大白话那句话是页面上第一眼看到的东西，不是埋在信息洪流中段的一段。依次是：朱砂大字吉凶加一个可执行短词（大吉 / 可进）、讲缘由的体用生克那句话、讲「这一卦说的就是你问的那件事」的那句、灰字「怎么算的」、宜 / 忌、以及提醒。下面的推导是「凭什么」，读不读都在那儿 |
| 右上角 | 同一个吉凶与体用关系，缩成一枚徽标。它跟结论块开头那个数是同一个数，页面上不会出现两个互相打架的吉凶 |
| 左侧 | 本卦与变卦的六爻图、卦辞、彖传、象辞；爻画左侧标六神，右侧标干支与六亲，世应用朱砂框标出，伏神用小字虚框挂在所属爻下，空破墓暗日破冲散合各作小标，用神那一圈的元神、忌神、仇神则各标在所属爻上；动爻标红打叉，本卦下方引动爻的爻辞与象传；六冲六合那十八卦，边上另有三支淡弧把初四、二五、三六接起来 |
| 右侧 | 体卦/用卦的五行、方位、主客、六亲世应、卦体冲合（本卦是六冲还是六合、变卦是什么）、用神（说清在哪一爻，或伏神伏在哪一爻）、日辰冲爻的暗动与日破与冲散、爻之合的合起合绊合好化扶、爻之刑的犯刑（谁刑了谁）、月令旺衰、旬空与月破、八宫名单（同宫八卦按世次排成一列，标出各卦变过的爻）、四卦推导图、卦气消长环 |
| 断语 | 十七到二十二段，第二段是「动爻爻辞」，含卦气、六亲世应与用神三段；写了问题会多一段「所问之事」。「暗动 · 日破 · 冲散」插在「用神」之后，只在真有爻被日辰冲到时才出，约四成六的卦有；「逢合 · 合起合绊合好化扶」排在「六冲」之后，只在真有爻逢合时才出，约八成一的卦有，四名各占约三成到五成，合好一成半；「犯刑」排在「逢合」之后，只在真有爻或日月刑到另一爻时才出，约九成的卦有（六十四卦里有 37 卦的纳甲本身就能碰出爻与爻相刑，余下的靠日月那一路补上）；「六冲」只在卦体本身是六冲或六合、变卦是六冲、或有动爻变冲时才出，约四成八的卦有；「反伏与卦变」排在「犯刑」之后，只在真有反伏或卦变时才出，手掷铜钱约 6.4%，时间、每日与数字三种起法恒动一爻，这一段在它们那儿永远不出 |
| 起卦依据 | 每个数怎么来的，全部摊开给你看，不藏 |
| 存入卦历 | 可以补一句批注，存进本机 |

断语里的**应期**是最实用的一段：它告诉你这件事大概在哪个地支对应的月份或日子会见端倪。

### 卦历

存下来的卦按时间倒序排在「卦历」分区，显示卦题、卦名、吉凶、时间和批注，可以单条删除。最多存 500 条。
这些只存在你自己的机器上，不上传任何地方。

### 在对话里起卦（MCP）

除了打开页面，你还能**完全不打开页面**，直接在对话里让 Agent 帮你起卦——它通过本应用注册的
MCP 端点调用本机上的推演逻辑。两种方式用的是同一套算法，结果一致。

#### 怎么确认能用

1. 本包要**装在 MiniMax Code 里**（复制到 `~/.minimax/plugins/chinese-divination/`，见下面的「安装」）。
2. **重启 MiniMax Code**，让 Host 读一遍插件目录、注册 MCP 服务器。
3. 然后直接说话就行，不用打开页面。

#### 怎么说，Agent 会怎么做

| 你说 | Agent 调用 | 关键参数 |
| --- | --- | --- |
| 帮我起一卦 / 看看现在怎么样 | `divination_cast` | `method: time`（默认，按当下时辰） |
| 今天什么日子 / 今天黄历 | `divination_almanac` | 无参数 |
| 谦卦什么意思 / 查一下水雷屯 | `divination_hexagram_lookup` | `query: 谦` |
| 掷铜钱 / 随机来一卦 | `divination_cast` | `method: coins`，本工具替你掷六次 |
| 今天这一卦 | `divination_cast` | `method: daily` |
| 我心里想着 3 和 8，起一卦 | `divination_cast` | `method: numbers`，`upper: 3` `lower: 8` |

你**不必**指定起法——Agent 会按你的话挑。想指定就直接说「用时间起卦」「掷铜钱」「按今天的日子起」。

**最重要的一点：把你问的事说出来。** Agent 会把你的原话填进 `question`，并自己判断它属于哪一类，
用 `topic` 报上来。只说「起一卦」而不说问什么，也能起，但认不出事类，应期只能退回按用卦推。

这个分工是刻意的。页面上没有能替你读问题的人，只能拿关键词去撞——「他对我还有没有真心」这类问法
表上一个词都没有。对话里 Agent 刚读完你问的什么，它不需要哪个词命中就能把这件事归到感情。
关键词那条路留着当退路：`topic` 不填时才轮到它。

#### 三个工具的参数与返回

**`divination_cast` — 起卦并解读**

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `question` | string，≤120 字 | 所问何事，原话即可 |
| `topic` | `wealth`/`career`/`love`/`marriage`/`health`/`study`/`property`/`dispute`/`journey` | 所问归九类中的哪一类。**由 Agent 判断**，不是关键词撞出来的；拿不准就省略，省略后由关键词表接手。决定类神五行、用神与应期，**不改变吉凶**。给了不在九类里的值会当场报错而不是悄悄忽略，让 Agent 知道自己没挑上 |
| `method` | `time`/`daily`/`numbers`/`coins` | 不填按 `time` |
| `upper` / `lower` | 整数 1–1e9 | 仅 `numbers` 用：取上卦 / 下卦 |

返回分两块：`content[0].text` 是给模型读的成文断语，`structuredContent` 是给程序用的结构化字段
（`method` / `question` / `topic` / `hexagram` / `changed` / `verdict` / `useGod` / `transforms` /
`dayClash` / `clash` / `fanfu` / `timing` / `disclaimer`）。`fanfu` 给出这一卦落在哪一档（`kind` 为「内卦」「外卦」「内外」「卦变」）、内卦与外卦各自反伏与否，以及反伏那一侧从哪一组纳支换到哪一组（`innerSwap` / `outerSwap`）；`useGod` 给出取了哪一亲；用神不上卦时，`hidden` 里
带着伏神——`position`、`hushen`、`feishen`、`flying` 与出伏结论 `emerges`；用神定下来时，`circle`
带着元神忌神仇神的爻位。`dayClash` 给出暗动、日破与冲散三路的爻位，成文抬头另有一行【日冲】，
真有可报时才出。`clash` 给出本卦是不是六冲卦或六合卦、变卦是不是、是六合变六冲还是六冲变六冲、
哪几个动爻变出来冲本位、初四二五三六三对各是什么判法，以及零散爻与爻冲的爻位对；抬头另有一行
【卦体】，真有可报时才出——出段率约四成八，所以那一行压得很短。抬头另有一行【反伏与卦变】，出段率约 6.4%，两档分开报、合并不了。两行都压得很短，模型不必再从成文断语里刨这几句话。
实际返回长这样：

```text
【起法】数字起卦
【所问】下个月要不要接这个offer
所问事类：事业功名（由 Agent 指定），类神五行 火。
【卦名】火地晋（第 35 卦，⚊⚋⚊⚋⚋⚋），上卦 离火、下卦 坤土

【断语】
【卦象总断】本卦火地晋，晋，康侯用锡马蕃庶，昼日三接。…

【大白话】
你问的是「下个月要不要接这个offer」。
我把它归到「事业功名」这一类——这一类以火为事。
这一卦给的是「大凶」，宜止。
体卦离火是你，用卦坤土是那件事——这件事要你往外掏；你被局面困住，处境受制。照两人之间的关系本该是凶，你这个月的状态把它拉到了「大凶」。
问的是事业功名，卦里说的就是这份前程——这件事要你往外掏，这一卦落在它上面不顺。
时间上：巳午月或巳午日见端倪，到辰戌丑未前后渐明。
该做的是：守成，不宜扩张、先处理内务再对外、避开正面对抗。别做的是：正面强争、额外投入与加码、在对方主场行事。
体用相制：局面不在你手上，宜守宜退，不宜正面强求。
【提示】本结果由传统占卜法按规则推演……（免责声明全文）
```

上面一半是家伙，下面一半是答案。

**最后那一块才是给你读的。** 上面那些是给 Agent 复述卦象用的——卦名、纳支、六亲、用神，整副家伙。
末尾的【大白话】是同一卦把术语撤掉之后的样子：

- **体卦是你，用卦是那件事。** 这是页面永远替你做不了、而 Agent 从来不必学的那一次翻译：
  叫「体」的那个经卦不是你的身体，是含动爻的那一卦，而那一卦就是求测的人。
- **旺相休囚死是你此刻有多少劲**，不是五个五行在月令里排第几。旺是「你此刻最有力气」，
  死是「你气力最弱，此时强推反而吃亏」。
- **生克关系变成一句谁对谁做了什么的话**：体生用读作「这件事要你往外掏」，
  用克体读作「外头的力压着这件事」。
- **两层对不上时它把差价讲开**。体克用单看生克是小吉，可体卦逢死地，总分被拉到平；
  白话把这一层讲明白，而不是留给你自己去怀疑算错了。
- 取象句、时间、宜忌与提醒也都在同一套说法里。

里面没有一句是新判断——每一句都来自上面已经定好的字段，卦象没定的东西它也不表态。
`initialize` 的提示语里交代了 Agent 照着这一段讲，而不是拿术语把卦象复述一遍。

**`divination_hexagram_lookup` — 查六十四卦**

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `query` | string，≤40 字 | 卦名、上下卦名或关键字，如「乾」「雷」「风」。省略则返回全表 |
| `limit` | 整数 1–64，默认 8 | 返回条数上限 |
| `detail` | `brief`/`full`，默认 `brief` | `brief` 省去彖传原文（约省 45% 篇幅），`full` 全给 |

**这个工具不会为你另起一卦。** 你问「谦卦什么意思」，它给你谦卦的辞义，不会顺手给你算一卦。

默认只给卦辞与象辞——查卦多半是问「什么意思」，彖传 61 字左右是「理」的层面，
Agent 多数时候用不上，所以默认省掉，末尾会有一句提示。要原文就传 `detail: full`。

```text
匹配「谦」的卦共 1 个，如下：

【地山谦】第 15 卦，⚋⚋⚋⚊⚋⚋，上坤下艮
卦辞：亨，君子有终。
象辞：地中有山，谦；君子以裒多益寡，称物平施。

互卦 雷水解，错卦 天泽履，综卦 雷地豫

（以上省去了彖传原文；需要时传 detail="full" 补上。）
```

#### 一个完整的往返

> **你**：下个月要不要接这个 offer？我有点犹豫。

Agent 调 `divination_cast`，`question` 填你的原话、`method` 用 `time`。你的话被认成「事业功名」，
类神取火，应期落在巳午。它用自己的语言把卦讲给你听——**断语文本由模型现场组织，
卦象由本应用按传统规则算出**。

> **你**：那如果不接呢？

它可以再起一卦（同一时辰仍是同一卦，若想不同就说「掷铜钱」），或换个角度用

#### 排障

**Agent 好像不知道有起卦这回事。**
最常见是没重启。Host 只在启动时扫一遍插件目录，MCP 服务器也是那时注册的。重启 MiniMax Code 再说。

**说「帮我起一卦」，它却没起。**
直接点一句「用梅花易数起一卦」，或说明「用灵签易占这个插件起」。随包的
`skills/divination/SKILL.md` 已经告诉它何时该起、何时只是查卦辞；遇到判断不了的情况，
你把起法说死即可。

**它没带免责说明。**
这是不该发生的——SKILL.md 里写的是每次转述卦象都必须带。你可以要求它补上。

**能不能不装就聊起卦？**
不能。页面和 MCP 都需要本包在 `~/.minimax/plugins/` 下被 Host 加载。

### 常见问题

**同一时辰起两次，结果一模一样？**
是。时间和日期是确定的数，同一个时辰当然得到同一个卦。想每次不同，用铜钱摇卦或数字起卦。

**问事真的有用吗，还是只是换个说法？**
问事决定事类与应期，不决定吉凶。同一时辰里问「换不换工作」和问「父亲手术要不要等」，
卦还是那个卦，吉凶还是大吉，但应期分别落在巳午和辰戌丑未，取象的侧重也不同。这是梅花易数本来的做法，
不是 AI 现编的。

**准不准？**
准不准取决于你自己。卦不预测未来，它把你已有的疑问摆到另一个角度，让你看清自己的处境与选择。
医疗、法律、财务等重要决定，请以专业意见为准。

**这些文字是谁写的？**
卦象按传统规则推演，是代码算的；把所有断语组织成通顺中文的是 AI。详见下面的「使用提醒」。

**我的问题记录会传到哪里？**
哪里都不传。存卦只写你自己机器上的 `context.dataDir`，应用不联网、不读包目录外的任何文件。

## 数据与访问

- 读取文件：本包内的 `miniapp/client/index.html` 与 Node 载荷目录，以及 `context.dataDir` 下的
  `readings.json`（凡碰到卦历的请求都会读它：列表、读单条、存入、删除）。除此之外不读取任何
  Host 文件、用户文件或其他路径。
- 请求参数一律校验。每一次按 id 取卦都必须匹配 `[A-Za-z0-9-]{1,80}`，于是写得进去的条目一定
  删得掉。起卦的起法名与数值上下界在进引擎之前就校验完。
- 存卦只收 `{ id, note }`，别的字段一概不收。那个 id 必须命中**本进程刚起出来的那一卦**
  （服务端保留最近 500 卦），所以落进 `readings.json` 的永远是引擎自己的产物，页面往里塞不了
  任何别的东西。批注是唯一的自由文本，上限 2000 字。同一 id 存第二次回 `409`——两条同 id 的
  记录会让删一条连带删另一条。有个副作用值得知道：一卦要在起卦的同一次会话里存入，服务端重启
  之后就不记得它了。
- 写入文件：`context.dataDir` 下的 `readings.json`。该目录由 Host 创建并归属本 Mini App，
  内含保存的卦象与批注，按时间倒序，最多 500 条。写入先落到同目录临时文件再改名，
  中途失败不会留下半截文件。改名在目标被别的进程短暂占住时退避重试——Windows 上杀毒扫描
  或搜索索引打开文件时就会这样。无法解析的 `readings.json` 会被改名另存为
  `readings.json.corrupt-<时间戳>` 而不是删掉，里面手写的批注捞得回来，卦历则按空表继续走。
  除该文件外不写任何位置。
- 网络：**无出站连接。** Node 进程不发起任何对外连接，页面不加载任何远程资源、字体或脚本，也不
  调用任何模型 API。MCP 端点只监听 Host 指定的回环地址 `context.listen`，只接受 POST。
- 子进程：不启动任何子进程。摇卦使用 Node 进程内的 `node:crypto.randomInt`。
- 凭证：不读取、不持有任何凭证，未申请 Host Connector 访问。
- 只有 `Host` 头指向回环、且带了 `Origin` 头时它也指向回环的请求才被受理。两个头各堵一条路：
  把自有域名解析到 `127.0.0.1` 的站点（DNS rebinding）由 `Host` 挡下，那时它带的是攻击者的域名；
  直接朝端口打过来的跨源请求由 `Origin` 挡下，那时 `Host` 反而是真的。缺头不当成伪造——Host 的
  MCP 客户端是 Node 程序，不发 `Origin`。被拒的请求回 `403`，且不回显任何东西。
- 日志只记错误码，不记错误文本。Node 的 fs 报错会把含操作系统用户名的完整绝对路径写进
  `error.message`；dataDir 按契约是不透明的，那串路径不离开这个进程——日志会被贴进 issue、被上传。
