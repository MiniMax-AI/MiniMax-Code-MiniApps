# Token 用量悬浮窗 / Token Usage Widget

一个圆形悬浮窗，实时显示你的 MiniMax 账号额度用了多少、烧得多快、最近 7 天用了多少。可以把它从
侧边栏弹成独立置顶窗口，鼠标悬停圆盘展开详情面板，在设置页里挑选要展示的指标。

[English](README.md)

## 展示什么

圆盘上同时有三个读数，每一处都可以自己选：

- **中心读数** —— 某一项指标的数字，例如当天的 Token 消耗量。
- **水面高度** —— 当前 5 小时或 7 天周期用了多少，以玻璃杯里的水呈现。
- **外圈进度** —— 第三项指标画成的进度环：周期用量、重置倒计时，或按当前速度推算 5 小时周期会
  被烧掉多少。

悬停圆盘会展开详情面板：列出你启用的每一项指标、最近 7 天的柱状趋势，并分别用一行说明中心、
水面、外圈各自对应哪一项 —— 这样选了速率类指标时，不必猜这个环指的是哪一段用量。

所有指标都来自你的 MiniMax 账号。圆盘里的趋势曲线取账号实时 Token 累计的差分，统计窗口由你选：
10 分钟、30 分钟、60 分钟或 2 小时。

设置页包含：

- **展示指标** —— 勾选、取消勾选，并拖动调整详情面板里的先后顺序。
- **刷新频率** —— 3 秒到 1 分钟。
- **悬浮窗** —— 5 档大小、重置位置，以及趋势曲线的统计窗口。
- **圆盘显示** —— 中心、水面、外圈分别显示哪一项。
- **外观** —— 主题（跟随系统 / 浅色 / 深色）与**语言**（跟随系统 / 简体中文 / English）。
- **数据来源** —— 账号数据源是否可用。

悬浮窗的大小与位置会被记住；界面语言默认跟随系统，也可以手动指定。

## 安装与打开

1. 下载或复制本插件目录，按 MiniMax Code 的本地插件说明装进去。
2. 在 MiniMax Code 打开 **Plugins**，启用 *Token Usage Widget*。
3. 从插件列表打开它，或者直接对 Agent 说「打开 Token 用量悬浮窗」。
4. 在页面上点 **悬浮窗模式**，把它弹成独立置顶窗口。

需要一个已登录的 MiniMax Code 账号：5 小时与 7 天周期进度、当天与最近 7 天用量来自 MiniMax
账号接口，速率与趋势取账号实时 Token 累计的差分。账号数据源取不到时，悬浮窗会在**数据来源**里
直接说明，而不是给一个撑不住的数据。

## 实测环境

- MiniMax Code 3.1.19，macOS 26.6.2。
- 最低客户端版本：**MiniMax Code 3.1.2** —— 本包声明了 `surface.window`，更早的客户端会直接拒装。
- 已在本机安装、通过宿主发布，并在内置 Browser 中验收：圆盘正常渲染，水面与外圈跟着各自的指标
  走，悬停展开详情面板且三个指标不滚动即可看全，7 天趋势柱状图正常绘制，控制台没有报错与警告。
- 四档趋势窗口都实测过：服务端按所选窗口每分钟返回一个桶（10 / 30 / 60 / 120 个桶），曲线按
  对应点数重画，无障碍标签也会写明窗口。
- 两种语言都实测过：语言设为跟随系统时按系统语言显示；切到简体中文或 English 后，圆盘、详情
  面板、设置页、指标名称与无障碍标签会就地整体重绘。
- 未验证：没有在 Windows 上实测；独立悬浮窗是通过内置 Browser 等价验证的，不是在 macOS 桌面上
  浮动窗口的实拍。

## 数据与访问

### 读取的文件

会读取一个属于 MiniMax Code 自身的文件。宿主没有为它提供 API，因此这依赖**未公开的内部目录
结构**，客户端版本之间可能变化。

| 文件 | 用途 |
| --- | --- |
| `<运行时根目录>/auth/**/auth.json` | 已登录的 MiniMax Code 访问令牌。只在 Node 进程内用于调用账号接口，绝不下发到页面、日志或响应体。 |

运行时根目录按 `$MINIMAX_DATA_DIR`、`$MAVIS_DATA_DIR`、`$MCODE_DATA_DIR` 依次尝试，最后回落到
`~/.minimax`。其下的目录结构未公开、可能变化；路径变动时悬浮窗会显示「该数据源不可用」，而不是
直接报错。

### 写入的文件

只写在宿主提供的 `context.dataDir` 里，本 Mini App 把它当作不透明路径：

- `settings.json` —— 启用的指标、刷新频率、主题、语言、大小、趋势窗口、中心／水面／外圈的对应
  关系与窗口位置。原子写入：先在同目录写临时文件，再改名覆盖。
- `account-rate.json` —— 把账号额度百分比换算成 Token 速率所需的采样历史：额度采样、账号当日
  累计采样与实时 Token 计数器采样。里面只有 Token 计数与时间戳，**不含任何凭据**。原子写入。

不会在 `context.dataDir` 之外创建、修改或删除任何文件。

### 网络主机

- `https://api.minimax.cn` —— 按登录区域选择的 MiniMax 账号接口。
- `https://api.minimax.io` 与 `https://api.minimaxi.com` —— 其它 MiniMax 区域的同一套账号接口。

请求打到 `/backend/account/token_plan/remains_percent`、`/usage_summary` 与
`/usage_overview`。访问令牌只作为 `Authorization` 头发往该账号主机。除此之外没有任何数据离开
本机。

### 启动的子进程

无。本 Mini App 不启动任何子进程。

### 其余项

- **Agent 运行**：无。本 Mini App 不会发起 Agent 运行。
- **读取对话**：无。
- **调用工具**：无。
- **麦克风、摄像头、通知**：无。
- **宿主导航**：不读取。页面会读取 MiniMax Code 的**主题**与**语言**以便跟随系统，这两项都不需要
  权限声明。
- **状态**：上述持久化状态存放在 `context.dataDir`。悬浮窗的大小与位置、当前显示的是悬浮窗还是
  设置页，作为视图偏好存在 `sessionStorage` 与 `localStorage`。
