# MiniMax Photo

把用户的自然语言需求转成可查看、可撤销的图片编辑。沿用用户选择的模型和输出要求；无需用户提供工具名、编辑器 ID 或脚本。

## 选择方法

- 先看用户附图和当前作品，识别需要保留和修改的部分。只有局部看不清、影响编辑决定时才裁切放大；风格化绘制通常不需要逐像素测量。 附件仅用于观察和参考绘制时，直接看图即可，不把导入画布或制作图片笔刷作为前置步骤；需要合成或修改原图像素时再导入。
- 单个简单修改直接调用编辑工具。多个相关操作优先先规划，再用一段 PTC 脚本顺序执行，减少模型来回调用。需要看中间结果才能决定下一步时，再拆开执行。
- 绘制路径、图层、选区和调色使用编辑器命令。用户要求模型生图或语义修图时，使用宿主实际提供的对应工具，再把结果导入编辑器。不要用生成的成品代替用户要求展示的绘画过程。
- 新作品使用新文档；修改已有作品时保留不相关内容，优先使用独立图层。根据画面选择构图、笔刷、路径和层次，不套固定题材模板。

## 连接和发现命令

1. 通过 `editor_list` 找到目标编辑器，再用 `editor_inspect` 确认当前作品及 `version`。本编辑器的 `engine` 是 `photocraft`，不要误选旧页面或其他引擎。
2. 下面列出的基础用法可直接使用；其他命令用 `photo_call` 的 `commands` 方法按需查询命令，例如 `args: {filter: "paint"}`。参数以当前返回的 schema 为准。过滤查询可减少上下文，不必先读完整目录。
3. 工具不可用时先确认插件已启用并打开；刚安装或更新后可能需要新会话刷新工具。不要通过搜索宿主源码、凭证或扫描端口绕过工具发现。

工具的宿主前缀可能变化，按当前工具列表匹配以下名称。`editor_capabilities`、`editor_batch`、`editor_preview`、`editor_create` 和 `editor_export` 是旧版 canvas 引擎接口。PhotoCraft 使用 `photo_call` 或下表的 PTC 方法；尤其预览用 `photo_call(method:"preview", args:{})` 或 `editor.preview()`，新建用 PTC `editor.create()`。

## 调用约定

直接调用：`photo_call({editorId, expectedVersion, requestId, method, args})`。
使用刚读取的版本和新的 UUID 请求编号。它返回排队中的任务；用 `editor_job({jobId})` 查询至完成，不能把已提交当作已完成。下一次直接调用使用成功结果的 `appliedVersion`。

批量脚本：`editor_run_code({editorId, expectedVersion, requestId, code})`，再用 `editor_code_result({runId})` 查询结果。脚本只能通过 `editor` 对象调用：

| 方法 | 用途与返回值 |
| --- | --- |
| `await editor.inspect()` | 直接返回当前状态，包括图层；不是任务包装对象 |
| `await editor.commands({filter})` | 完成的任务对象；命令数组在 `job.result.value` |
| `await editor.create({width,height,name})` | 新建文档，返回完成的任务对象 |
| `await editor.execute({command,params})` | 执行单个命令，返回完成的任务对象 |
| `await editor.edit([{command,params}, …])` | 执行一批命令，返回完成的任务对象 |
| `await editor.draw({strokes, intervalMs:550})` | 真实逐笔绘制；strokes 是 paint.stroke 的参数数组，1..96 笔，间隔 100..600ms；每笔单独撤销，中断保留已完成笔触 |
| `await editor.preview(options)` | 查看画面，返回完成的任务对象 |
| `await editor.export(options)` | 按查询到的导出参数保存，返回完成的任务对象 |

编辑任务包含引擎结果包装，不要假设新图层 ID 在 `result.value.id`；创建后用 `editor.inspect()` 读取图层。`layer.select` 使用 `{layer: 图层ID}` 或 `{name: 唯一图层名}`，不是 `{id: …}`。`layer.setProps` 修改已选择的图层，其中 `name` 是重命名，不是选择器。先选图层再设属性；新建绘画层默认保持透明，纸底只画在底层。其他命令仍查询实际 schema，不猜参数。

`paint.stroke` 和 `draw` 每笔还可显式传 `layer: 图层ID`，跨图层绘制或擦除时优先指定，避免依赖当前选择。`erase:true` 或 `mode:"clear"` 擦除目标图层的像素，不会自动隔离同层的某一类笔触；锁定透明度的图层会改为涂背景色。擦除前检查目标层及锁定状态，不把露出的下层颜色直接判断为所有图层被擦除。

脚本内逐个 `await`，不能 `Promise.all` 或漏掉等待。可使用循环和辅助函数组织几何路径、重复笔触及条件分支。没有 Node、文件或网络 API。每段代码上限 32 KB、最多 64 次编辑 API 调用、120 秒；按工作量合理拆分，不为了“一次完成”超过限制。

`console.log/info/warn/error/debug` 可记录调试信息；完成后从 `editor_code_result` 的 `logs` 读取，最多 50 条、总计 10000 字符，超出截断。返回业务数据仍用 `return`，不要把日志当作编辑成功的证明。

## 执行与验收

- 一段脚本可以按实际编辑阶段多次 `editor.edit`，每批提交后画布更新。每批是一个撤销步骤；整段脚本不是一个事务。批次根据独立修改和耗时划分，不按固定数量拆分，也不为演示添加空操作或等待。
- 用户要看绘画过程时，用 `editor.draw` 提交笔触，而不是 `edit` 一次提交整幅线稿。演示或录制时使用 500–600ms 间隔，确保每笔可辨；不要为追求快而压到 100ms。可以在同一段 PTC 中生成路径、分组逐笔绘制，不必每笔都请求模型。按总显示时间留出 120 秒脚本预算；阶段间查看预览后再继续。
- 显示 AI 操作轨迹开启时，笔画在提交后短暂回放；这不是逐像素实时绘制，也不是系统鼠标移动。不要把轨迹回放描述成模型手动画笔。
- 完成后查看预览，对照用户要求检查结构、边界、遮挡和可读性；需要时做局部修正。任务成功不等于视觉验收成功。按用户需要导出图片或保留图层的工程，只报告实际生成的文件。
- 失败时先查运行 `trace` 和其中的任务编号，再读当前状态；前面成功的批次可能已保留。只修复失败部分，不盲目重放整段脚本。版本冲突可能来自自己上一段脚本的修改，不代表用户插手。独立脚本开始前重新 inspect；同一脚本内版本由工具自动跟踪。任务仍在执行时查询原任务，不提交新请求。
- 请求结果未知时查询原请求；相同请求编号只用于同一份请求的重试。新操作使用新 UUID，避免重复绘制或误把旧结果当作新结果。

## 参考绘画与素描

- 简单插画、标志等色块边界清楚，且用户强调相似度时，优先使用随 Skill 提供的轮廓脚本，见 [参考图轮廓转笔触](references/reference-tracing.md)。它输出真实逐笔绘制的数据，不是成品图片；不要临时重写边界遍历或平滑算法。照片、复杂纹理不适合直接按颜色提取，改用观察后的简化曲线。
- 一轮用户请求内完成观察、绘制、预览和必要的局部修正。可以分几次 PTC 调用，避免超时；不要把内部阶段变成要求用户继续发送的步骤。轻稿已像原图时，补少量明暗即可，不以反复加细节拖长简单素描。

- 先判断整体比例、轮廓曲率、遮挡和留白；信息足够就画轻稿并看预览，不反复裁图测坐标。轻稿阶段把预览与附件对照，确认主体类别、轮廓比例、关键部件和相互位置仍可识别，再铺明暗。允许自由发挥不等于替换主体或改变关键结构；用户更重视相似度时，简单准确优先于精细。
- 用平滑曲线采样笔触，避免少量折线点把圆润形体变成多边形。先轻线确定形，再用少量重点线强调结构；不要给所有边缘同样粗黑的描边。
- 素描先确定光源与大块明暗。用宽、淡的笔触铺体积，再用顺形排线和少量交叉排线丰富层次；接触阴影比普通暗部更深，高光留白。随机短线和颗粒不能代替体积。
- 铺调子前，先按形体划分连贯的亮面、灰面、暗面，考虑前后遮挡；不要用孤立灰斑或等距同心弧线代替受光变化。轮廓、灰面和细节分层，灰面需要限制边界时先建立选区或蒙版，保留轮廓线所在层。蒙版的创建与编辑是不同命令，查询对应 schema 后使用。
- 首次使用不熟悉的笔刷铺大面积调子时，在临时层画少量小样并查看实际效果，再选参数正式绘制，随后移除试笔层。笔宽、透明度、压力和预设会共同影响结果；不能仅凭传入的数字断言最终灰度。笔刷已验证时直接复用，不必每次试笔。
- 缩小预览检查构图和明暗，放大检查交接处、眼睛等视觉重点。比例歪、轮廓交叉、擦除残影或阴影像装饰条纹时先修正，再加细节；工具成功不等于作品完成。
- 同一区域反复修改却没有改善时，先比较修改前后的预览，区分形体、遮挡、笔刷参数或图层状态问题，再更换方法；不要继续盲目加深或加密。完成时隐藏辅助线与试笔，确认画面没有意外穿插、溢出和未收尾的区域。

`paint.stroke` 的 `opacity` 是 0–1，填充命令的 `opacity` 通常是百分比，以各自 schema 为准。排线只用于补充质感，先用低硬度、低透明度的宽笔触建立连续灰面。

### 曲线笔触

`editor.draw` 的每笔可使用 `points`，也可用 `path` 表达连续曲线，二者选一。`path` 使用绝对坐标，格式与 SVG 命令一致：`["M",x,y]` 起点，`["L",x,y]` 直线，`["Q",cx,cy,x,y]` 二次曲线，`["C",c1x,c1y,c2x,c2y,x,y]` 三次曲线，`["Z"]` 闭合。工具负责曲线采样，无需手写样条插值。每笔只含一个 M；断开的部分分为多笔。可额外设置 `pressure:0..1`；颜色、笔宽、透明度等仍为 paint.stroke 参数。

圆润轮廓用 C/Q，硬质折面用 L，不要把整个主体替换成一个圆。绘图前保留参照物之间的相对位置和遮挡，风格化不等于丢掉识别特征。笔触超过 96 条时，用循环按 96 条切片顺序调用 draw；展示间隔默认 550ms，估算总时长并在 120 秒预算内分阶段。

### 基础绘图用法（本包已验证）

不用为了画简单线条先读完整画笔字段或预设目录。`editor.create({width,height,name})` 建画布后，新建透明图层：

```js
await editor.execute({command:"layer.new.layer", params:{name:"Sketch"}});
const layerId = (await editor.inspect()).document.activeLayer;
// 日后回到此层用 layerId，不依赖名称或图层顺序。
await editor.execute({command:"layer.select", params:{layer:layerId}});
await editor.draw({intervalMs:550, strokes:[{
  path:[["M",40,90],["C",70,20,150,20,180,90]],
  size:2, color:"#555555", opacity:0.65, pressure:0.7
}]});
```

这只示范调用方式，不是作品模板。需要改可见性或不透明度时，`layer.setProps` 接受 `{layer:layerId, visible:true, opacity:0.8}`；不需要填写 name。宽、淡的柔和阴影可用 `paint.stroke` 的 `hardness:0..1`（低值软边）、`size`、`opacity:0..1`，不必引入随机纸纹来掩盖结构。

### 限制笔触范围（已在宿主验证）

铺连续明暗时，可先调用 `select.lasso`：`params:{points:[[x,y],…], mode:"replace", antiAlias:true, feather:0}`。`points` 是沿目标边界排列的多边形顶点；`mode` 还支持 `add`、`subtract`、`intersect`。用 `subtract` 排除需要留白或被遮挡的部分，再在独立灰度层用宽软笔逐笔铺调子，笔触会被选区裁剪。范围由当前作品决定，不复用固定形状。结束后调用 `select.deselect`，参数 `{}`，避免后续笔触被旧选区意外截断。

局部修复先检查目标层：轮廓、阴影和纹理混在同层时，宽橡皮可能同时擦出断口或白块。优先回退失败笔触或在独立层修补；修后查看交接处，不只确认杂线消失。
