# MiniMax Photo

把用户的自然语言需求转成可查看、可撤销的图片编辑。沿用用户选择的模型和输出要求；无需用户提供工具名、编辑器 ID 或脚本。

## 选择方法

- 先看用户附图和当前作品，识别需要保留和修改的部分。只有局部看不清、影响编辑决定时才裁切放大；风格化绘制通常不需要逐像素测量。
- 单个简单修改直接调用编辑工具。多个相关操作优先先规划，再用一段 PTC 脚本顺序执行，减少模型来回调用。需要看中间结果才能决定下一步时，再拆开执行。
- 绘制路径、图层、选区和调色使用编辑器命令。用户要求模型生图或语义修图时，使用宿主实际提供的对应工具，再把结果导入编辑器。不要用生成的成品代替用户要求展示的绘画过程。
- 新作品使用新文档；修改已有作品时保留不相关内容，优先使用独立图层。根据画面选择构图、笔刷、路径和层次，不套固定题材模板。

## 连接和发现命令

1. 通过 `editor_list` 找到目标编辑器，再用 `editor_inspect` 确认当前作品及 `version`。本编辑器的 `engine` 是 `photocraft`，不要误选旧页面或其他引擎。
2. 用 `photo_call` 的 `commands` 方法按需查询命令，例如 `args: {filter: "paint"}`。参数以当前返回的 schema 为准。过滤查询可减少上下文，不必先读完整目录。
3. 工具不可用时先确认插件已启用并打开；刚安装或更新后可能需要新会话刷新工具。不要通过搜索宿主源码、凭证或扫描端口绕过工具发现。

工具的宿主前缀可能变化，按当前工具列表匹配以下名称。`editor_capabilities` 和 `editor_batch` 是旧引擎接口，不能代替 Photo 的 `commands` 和 `batch`。

## 调用约定

直接调用：`photo_call({editorId, expectedVersion, requestId, method, args})`。
使用刚读取的版本和新的 UUID 请求编号。它返回排队中的任务；用 `editor_job({jobId})` 查询至完成，不能把已提交当作已完成。下一次直接调用使用成功结果的 `appliedVersion`。

批量脚本：`editor_run_code({editorId, expectedVersion, requestId, code})`，再用 `editor_code_result({runId})` 查询结果。脚本只能通过 `editor` 对象调用：

| 方法 | 用途与返回值 |
| --- | --- |
| `await editor.inspect()` | 直接返回当前状态，包括图层；不是任务包装对象 |
| `await editor.commands({filter})` | 完成的任务对象；命令数组在 `job.result.value` |
| `await editor.create({width,height,name})` | 新建文档，返回完成的任务对象 |
| `await editor.execute({command,params})` | 执行单个命令，返回完成的任务对象 |
| `await editor.edit([{command,params}, …])` | 执行一批命令，返回完成的任务对象 |
| `await editor.preview(options)` | 查看画面，返回完成的任务对象 |
| `await editor.export(options)` | 按查询到的导出参数保存，返回完成的任务对象 |

编辑任务包含引擎结果包装，不要假设新图层 ID 在 `result.value.id`；创建后用 `editor.inspect()` 读取图层。`layer.select` 使用 `{layer: 图层ID}` 或 `{name: 唯一图层名}`，不是 `{id: …}`。其他命令仍查询实际 schema，不猜参数。

脚本内逐个 `await`，不能 `Promise.all` 或漏掉等待。可使用循环和辅助函数组织几何路径、重复笔触及条件分支。没有 Node、文件或网络 API。每段代码上限 32 KB、最多 64 次编辑 API 调用、120 秒；按工作量合理拆分，不为了“一次完成”超过限制。

## 执行与验收

- 一段脚本可以按实际编辑阶段多次 `editor.edit`，每批提交后画布更新。每批是一个撤销步骤；整段脚本不是一个事务。批次根据独立修改和耗时划分，不按固定数量拆分，也不为演示添加空操作或等待。
- 显示 AI 操作轨迹开启时，笔画在提交后短暂回放；这不是逐像素实时绘制，也不是系统鼠标移动。不要把轨迹回放描述成模型手动画笔。
- 完成后查看预览，对照用户要求检查结构、边界、遮挡和可读性；需要时做局部修正。任务成功不等于视觉验收成功。按用户需要导出图片或保留图层的工程，只报告实际生成的文件。
- 失败时先查运行 `trace` 和其中的任务编号，再读当前状态；前面成功的批次可能已保留。只修复失败部分，不盲目重放整段脚本。版本冲突表示作品被改动，需要重新读取再决定后续编辑。
- 请求结果未知时查询原请求；相同请求编号只用于同一份请求的重试。新操作使用新 UUID，避免重复绘制或误把旧结果当作新结果。
