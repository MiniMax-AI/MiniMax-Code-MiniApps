# MMX 章鱼娘

*住在你桌面上的小章鱼：她跟着 Agent 的状态走，也能被 Agent 指挥着说话。*

English | [简体中文](README.zh-CN.md)

作者：[antianqi](https://github.com/antianqi) · 版本：`1.9.0` ·
插件 ID：`mmx-octopus` · 分类：`Productivity`

## 它做什么

- **她跟着 Agent 走。** 她订阅宿主的 Agent 轮次事件
  （`turn.started`、`message.committed`、`turn.finished`）并切换表情：
  轮次开始是 `thinking`，任务在跑是 `working`，这一轮真有产出是 `celebrate`。
- **她报这一轮的尾。** 一轮结束时她说一句关于结果的话 —— 有正文就摘要，
  没正文就用一句兜底话报出会话名。
- **她有自己的一间聊天室。** 面板里有聊天区。你给她发一句话，她就在**自己的
  会话里跑一轮 Agent**，然后用自己的语气回答你：短句，一句一条气泡地冒出来。
- **她写日记。** 面板里的日记本写的是她自己的独白，和聊天记录分开存，她自己写。
- **Agent 能指挥她。** 这个包自带一个 MCP 服务器，四个工具（见下），
  Agent 可以让她说话、换表情、挪位置、读她的状态。
- **她也可以用自己的 agent 回答 —— 但那个 agent 得你自己建。** 插件不会替你建 agent，
  也不会往宿主写 agent 文件。想让她有自己的 agent：打开面板（设置 →「想要更鲜明的性格？」），
  点 **「复制她的设定」**，她的设定正文会进你的剪贴板；到 MiniMax Code 的 Agent 设置里
  新建一个叫 `mmx` 的 agent，把设定粘进去保存，插件就会自己认出它（只读）并用它回答。
  不建也行：她用默认 agent 回答，设定每轮随消息带。
- **她不挡路。** 浮窗无边框、透明、置顶、鼠标穿透，永远不挡住桌面。
  尺寸 220 × 460，可以拖到屏幕任意位置；Agent 也能把它停到四个固定位之一（三个角 + 屏幕中间）。
- **怎么再找到她。** 浮窗是鼠标穿透的，所以它不会吞掉你的点击：把指针移到她身上，
  那一块会自动关掉穿透 —— 点她是有反应，按住拖就是挪她。也可以在面板里选固定位
  （设置 → 「停靠位置」），**浮到桌面之后才生效**。浮窗是宿主开的另一个独立窗口，
  关它就按关宿主窗口的办法；面板一直在跑，随时能再把她浮出来。

## 安装

把整个 `mmx-octopus` 目录（含隐藏目录 `.minimax-plugin`）复制进 MiniMax Code 的数据目录：

```text
仓库目录：mmx-octopus/
安装到：  <dataDir>/plugins/mmx-octopus/
清单文件：<dataDir>/plugins/mmx-octopus/.minimax-plugin/plugin.json
```

默认数据目录是 `~/.minimax`，所以通常装到 `~/.minimax/plugins/mmx-octopus/`。

重启 MiniMax Code，确认插件被识别并启用，然后从插件列表打开 **MMX 章鱼娘**。
浮窗会出现在桌面上；面板里有她的状态、聊天区和日记本。

不需要别的：没有 API key，没有账号，没有依赖要装。

## 使用

1. 从插件列表打开它，浮窗就出来了。
2. 把它拖到某个角，或者让 Agent 用 `mmx_move` 挪。
3. 照常跟 Agent 说话，看她的表情跟着走。
4. 打开面板跟她说话 —— 她在自己的会话里回答。
5. （可选）给她一个自己的 agent —— 在面板里复制她的设定，粘到新建的 `mmx` agent 里（见「它做什么」）。

### Agent 的四个工具

这个包托管一个 Streamable HTTP MCP 服务器（`mmx`），由 `miniapp.json` 挂在
`/mcp/mmx` 上。宿主会改写它的地址，并像对待端口上其他东西那样给它做鉴权。

| 工具 | 作用 |
| --- | --- |
| `mmx_say` | 弹一个气泡说一两句话 —— 工具要求不超过 120 字，运行时会拒收超过 300 字的内容。适合用作任务完成通知。 |
| `mmx_mood` | 切表情：`idle`、`thinking`、`working`、`celebrate`。 |
| `mmx_move` | 把浮窗挪到四个固定位之一：`bottom-right`、`bottom-left`、`top-right`、`center`。 |
| `mmx_status` | 读她当前的表情、当前的气泡，以及 Agent 是否在跑。 |

## 她的身体是怎么动的

- **94 段带 alpha 通道的短片**放在 `miniapp/client/assets/webm/`，
  清单在 `miniapp/client/assets/webm/manifest.json`。它们是主力，不是兜底。
- 片子从**池**里取，池跟着**轨**走，两个 `<video>` 当**双缓冲**：前面那个在播，
  后面那个在装下一段，所以两段之间不会断。
- **兜底是真的在。** 池里没东西可播、连续三次装不出、或一段迟迟不来时，
  由 CSS 变换的 `pose` 轨接管（呼吸、点头、轻轻一跳）。片子还在加载的时候，
  你看到的就是它。
- **没有口型。** 片子是她的静态图，嘴不会跟着词动。这是取舍，不是 bug。

## 已验证环境

- MiniMax Code 3.1.7 on Windows 11 (x64)。
- 这个包**要求 MiniMax Code 3.1.5 或更高**：它声明了
  `agentAccess: ["session.read", "session.run"]`，比 3.1.5 老的客户端会直接拒装整个包，
  而不是只装一半。
- 需要支持 MiniApp 与 Agent 轮次的桌面客户端。
- 附带的自检脚本需要 Node 22 或更高。

## 数据与访问

- **读什么** —— 读这个包自己的文件，从 `context.pluginRoot` 读：
  `miniapp/node/identity/AGENTS.md` 和 `miniapp/node/identity/STORY.md`（她是谁），
  以及 `miniapp/client/` 下的页面素材；还读宿主列出来的 agent 列表 ——
  **只读**，用来决定由哪个 agent 回答她。
- **写什么** —— `context.dataDir` 下四个 JSON 文件，也就是宿主给这个包建的私有目录，
  **这个目录之外它一个字节都不写**：
  `context.dataDir/state.json`（她的表情、位置、气泡，以及 Agent 忙不忙），
  `context.dataDir/chat.json`（你和她的聊天），
  `context.dataDir/diary.json`（她的日记）、`context.dataDir/style.json`（她学到的语气）。
  每次落盘都是原子的 —— 先写同目录临时文件，再改名 —— 所以崩了也不会留下半个文件。
- **`context.dataDir` 之外不写任何文件（1.9.0 起）** —— 运行时**再也不新建任何文件**：
  不建 agent 文件，不往宿主的 agent 目录写，不碰你的项目。它碰到的文件只有上面
  那四个 JSON。
  - **面板上那个二选一没了。** 1.8.0 面板上的「她用哪个 agent」（「建专属 agent」/
    「用现有 agent」）已经去掉，随它一起去的还有那条手动命令 `agentprov-cli.mjs`，
    没有什么可切的了。
  - **你自己那个 `mmx` agent，得你建。** 面板上的 **「复制她的设定」** 只是把她的设定正文
    交给你（一个字节都不写盘），你把它粘到 Agent 设置里新建的 `mmx` agent 上；插件之后
    通过宿主的 agent 列表**认出来**并用它回答，全程只读。建、改、删都是你的事。
  - **agent 列表它还是会读 —— 只读。** 插件读宿主列出来的 agent 列表；如果你自己
    建过一个叫 `mmx` 的 agent，她就用那个来回答。**你的 agent 不会被改，也不会被写**；
    没有 `mmx` agent 就退回默认 agent。
  - **她的设定随消息带。** 没有专属 agent 替她存着这份底稿了，她的身份（她是谁 /
    她长什么样 / 她的规矩）就每一轮随消息带进会话 —— 见下面「她的身份怎么送到她那儿」。
- **老版本留下的东西** —— 1.7.0 之前的版本会把一份 `AGENTS.md` 写进「装了本插件的那个 agent」
  的工作区，用来把她的身份放在那儿。**现在不再写了，也不再需要它**。从老版本升级的话，
  那份文件可能还在（`agents/<agent>/miniapps/<plugin-id>/AGENTS.md`），可以直接删 ——
  运行时不会去动它：**插件不许写自己 dataDir 之外的文件**。1.8.0 那次可能留下的
  agent 目录，见下面「从 1.8.0 升级」。
- **她的身份怎么送到她那儿** —— **每一轮随消息带（弱通道）**。她的底稿、样子和规矩从本包自己的
  `miniapp/node/identity/AGENTS.md` 读出来，拼进每次的提示词里，所以每一轮都带着它。
  ⚠️ 代价：这一份走的是会话历史 ⇒ 宿主做上下文压缩时可能把它压掉（所以每轮都重发一份）。
  1.9.0 起这就是**唯一**一条路：不再往任何 agent 文件里写她的底稿了，每轮随消息带的
  那份就是唯一的一份。
- **读哪些会话** —— 这个包声明了 `session.read`。它读一轮对话的标题、运行状态和最终回复，
  用来分辨 Agent 是在想还是做完了，也用来给这一轮做摘要。面板里的看板列出正在跑的会话，
  每 30 秒刷新一次。
- **会跑哪些 Agent 轮次** —— 它声明了 `session.run`，并且**你在聊天区给她发的每一句话，
  都在她自己的会话里跑一轮 Agent**。这一轮走宿主的 Agent，因此带着宿主给那个 agent 的权限；
  它会读宿主的 agent 列表；如果你自己有一个叫 `mmx` 的 agent，就用它来回答
  （**只读，不会改你的 agent**）；没有 `mmx` agent 就退回默认 agent。
  它不会去跑你自己的会话。
- **它自己会起的那些轮次** —— 除了你发的消息，运行时还会自己起几轮，**每一轮都花你的模型额度**：
  - **闲话**：**默认关着**，要她主动开口自己在面板里开：设置 → 「她没人的时候自己说话」。
    开了以后，你安静 20 分钟后她可能自己开口；一小时最多 2 轮，两轮之间至少隔 45 分钟。
    **同一个开关也能再关掉**。
  - **写日记**：聊完天，如果今天还没有日记，她会写一篇。
  - **学语气**：聊完天，你最近的聊天记录会送给模型，让她学你说话的样子。
  - **回你给日记写的评论**：每条评论再跑一轮。

  她的静态台词（打招呼、「好久没人理我了」、「你刚才不理我」）**不走模型、不花额度** ——
  关掉闲话只停模型那几轮。
- **别的会话标题** —— 「她知道我在忙什么」**默认开着**，这时你**其它会话**的标题与运行状态
  会进她的提示词，她才知道你在忙什么。**面板里能关**：设置 → 「她知道我在忙什么」。
- **会调用哪些工具** —— 只有它自己那四个 MCP 工具，走它自己的端口。
  不调用 connector、不调用任何厂商服务、不调用任何第三方服务。
- **进程** —— 不起。这个包不 spawn 任何子进程，也不跑任何外部二进制。
- **网络** —— 只有这个 Mini App 自己的 loopback 地址。页面通过宿主鉴权过的 loopback 端口
  和运行时说话，运行时也只通过同一个端口和宿主说话。没有任何指向别的 host 的出站请求，
  也不读、不存、不转发任何凭据。
- **麦克风** —— 从不。这个包没有声明 `deviceAccess`，也不申请任何浏览器权限。
- **状态放在哪** —— `context.dataDir`。把它当成不透明路径：版本之间可能变，别写死。

### 从 1.8.0 升级

1.9.0 改的是插件和宿主 agent 的关系，不只是一个版本号：**它不再创建任何 agent 文件**，
面板上的「建专属 agent / 用现有 agent」二选一，以及跟着它的手动命令 `agentprov-cli.mjs`，
一并没了。

- **如果你用过 1.8.0** 并让它建了专属 agent，宿主的数据目录里可能还残留
  `<宿主数据目录>/agents/mmx-octopus-agent/` 目录，**可以手动删掉** ——
  里面的东西已经用不上了。
- **1.9.0 不会再创建它，也不会再去碰它。** 它只写 `context.dataDir` 下那四个 JSON。
- **你自己那个 `mmx` agent 照旧优先。** 你要是有叫 `mmx` 的 agent，她就用它来回答 ——
  **只读**，插件不会改它。
- **1.9.0 还多给了你一份设定。** 面板上的 **「复制她的设定」** 会把她的设定正文给你，
  你可以自己建一个叫 `mmx` 的 agent 把她放进去 —— 插件不再替你建，只负责认。

## 已知限制

- 界面只有中文。
- 没有语音：气泡就是文字。
- 身体动画只覆盖片子里有的那些瞬间；片子之间跑的是 `pose` 兜底。
- 她用宿主给她解析到的那个 agent 回答。
- 没有你自己建的 `mmx` agent 时，她的设定就走「每轮随消息带」这条路，
  而宿主做上下文压缩时可能把它压掉（所以每轮都重发一份）。
