# 节点画布

MiniApp 就是这块画布，Agent 通过 `canvas` MCP 服务器碰它：`canvas_list`、
`canvas_read`、`canvas_list_templates`、`canvas_add_node`、`canvas_connect`、
`canvas_update_node`、`canvas_apply_template`、`canvas_remove_node`、`canvas_run`。

**画布上有一条现成工作流。** `canvas_list_templates` 列出它们：`图片复刻`、`视频模仿`，
以及 H3 的五种形状（文生视频 / 首帧 / 首尾帧 / 末帧 / 全参考）。`canvas_apply_template`
把其中一条铺到画布上——**铺完不跑**，跑起来才花钱；铺完的链是空的骨架，缺的素材要用户自己放。

**画布是什么。** 节点是一次模型运行，连线把上游做出来的东西送到下游。跑完的产物**直接落在
跑过的那张卡上**，不另长一张结果节点 —— 所以别去等「结果节点」，产物就在生成卡里。
结果节点只剩工具和批量产物两种来处；它们（以及用户自己放了图片的输入节点）就是下一步
加工的原料：抠图、变清晰、切九宫格、读回来。

## 先想该用不用提示词增强

生成节点把提示词框里的文字**原样**送给模型（提示词框在卡片下面的操作面里）。
当模型对某个任务有成文的格式时，手写那个格式就是白干。

**text 节点在 `prompt` 模式（提示词增强）**就是那个格式：它跑一轮文本，把一句粗话
重写成那个格式，画布上提供这些模板：

| 模板 | 什么时候用 |
| --- | --- |
| 电商主图 | 产品主图：主体 + 材质细节 + 场景光线 + 构图视角 + 画质 |
| 短视频分镜 | 分镜表：时间码 + 景别 + 运镜 + 动作 + 情绪 + 音效 |
| 人物写真 | 人像：外貌 + 服装 + 姿态表情 + 光线 + 背景 + 镜头画质 |
| 产品质感 | 产品特写：材质结构 + 使用场景 + 光影 + 微距细节 + 背景 |
| 社媒封面 | 封面：主标题 + 视觉主体 + 配色 + 留白排版 + 平台尺寸 |
| **H3 T2VA / I2VA / FL2VA / L2VA / 全参考六段** | **任何 MiniMax H3 视频请求** |

H3 那几个是 provider 自己的提示词写作指南，带着 H3 最吃的三段结构
（`integrated_multimodal_description` 画面时间线、`overall_soundscape` 环境音与
非语言人声、`non_diegetic_music` 只有观众听得见的配乐），和配套的写法约定：切点用
`[Shot N] At MM:SS.mmm`，运镜写成"运动类型 + 幅度 + 速度"的自然句，说话人写
`(S1)`，台词写 `<d>[语言] 台词</d>`，跨切写 `<scenetrans>`。结构用英文写，台词保留
原语言。

**提示词节点省下的是什么。** 点名那张图和时间戳的对齐行**由运行时写**，不由提示词
写 —— 但只有当提示词的其余部分已经是它期待的结构时才对齐。手写一条 H3 提示词会丢掉
结构、镜头记法和声音层，成片会很平。提示词节点花一轮文本，换回来一条视频模型看得懂
的提示词。

**怎么点名。** `canvas_add_node` 和 `canvas_update_node` 都接受 `templateId`，模板的
正文会跟着一起带上：`ecommerce-main`、`short-video`、`portrait`、
`product-texture`、`social-cover`、`h3-t2va`、`h3-i2va`、`h3-fl2va`、`h3-l2va`、
`h3-reference`、`custom`。自己写 `templateText` 就替换掉模板的正文。不点名的话取第一个
模板 —— 所以还没打字时它也是有用的。

**提示词节点不做的一件事。** 它不写对齐行，也不自己编引用编号。那两样归运行时。

## 引用编号由请求决定

连线进生成节点，就成了请求里的一个参考，运行时给它们编号 —— 和提示词里参考素材块
的编号是同一套。编号跟的是**请求**，不是卡片标题、也不是画布上的位置：一个节点上游接了
两张图，哪张是 1 由请求决定，不是你决定。

编号的**写法跟着模型走**，因为各家的接口各认各的写法：

| 节点 | 写法 |
| --- | --- |
| 图片节点（MiniMax-H3-Image） | `图1`、`图2` —— 这个接口按位置点名参考图，提示词里就写 `图1` |
| 视频节点（H3 家族） | `@图片1`、`@视频1`、`@音频1` |
| 文本节点 | `@图片1`（文本模型看不见图，是运行时先读再转述） |

所以给**图片**节点写提示词时点名写 `图1`，给**视频**节点写才写 `@图片1`。

`prompt` 模式节点旁边有模板下拉和模板文本框，用户可以自己改；Agent 走的是同一条规则。

## 值得搭的链

- **文字 → 图 → 视频。** 文字节点（或提示词节点）→ 图片节点 → 视频节点。图自动成为
  视频的首帧，它拿到的编号就是对齐行里写的那个。
- **一张图再加工。** 跑出图的生成卡（或者用户自己放了图的输入节点）→ 那张卡上的工具（抠图、
  变清晰、切九宫格、剪裁、换机位、换光、AI 抠图、AI 放大）。工具会留下自己的
  结果节点，所以链能一直接下去。
  **这些工具在卡片上，不在 MCP 上** —— Agent 够不着它们，只能告诉用户点哪个。
  **AI 放大只收长边 ≤2048 的图**，画布自己出的 4K 图超限，要先用「剪裁」把尺寸弄到
  2048 以内。
- **一段片子再加工。** 视频卡上只挂两个按钮：**分离音频**（把声音单独取出来）和
  **剪辑**（在素材上裁出一段）；音频卡上挂一个：**剪辑**。剪辑浮层里那条带子就是素材
  本身（视频是一排抽帧，音频是真实波形），两端可以拖；范围永远落在素材里，也不会短到
  0.2 秒以下。带子下面是一条走带行（播放键 + `00:00 / 00:15` 的时钟），素材在上方的
  节点卡里播（视频看得见画面、音频听得见声，选中的那一段循环播放，拖手柄时画面跟着
  手走），用户是边听边选的。剪辑浮层挂在**卡片下方居中**，不压在卡片上。
  条带上有一根**播放头**：标出「现在播到哪儿」，自己跟着声音走；按一下条带就把素材
  切到那一点，拖着走也跟着手 —— 想剪的那一帧可以先听再确认。它**也能被抓住**（线很细，
  左右各留了 22 像素的抓手，抓住是从当前位置挪走，不跳），还是滑块：方向键 10 毫秒
  一格、Shift 1 秒、Home / End 到两头。
  选区**要留的那段是亮的、要剪掉的那段被压暗**（不是蒙一层蓝），选区两端是**细线 +
  三个小点**（不是实心色块）；浮层自带**「取消 / 确认」两个按钮**，**Esc** 也能关浮层。
  音频卡上**不挂浏览器那条灰播放器**，而是自己画波形：**上面一条波形带、下面一条走带行**。
  波形带上**播过的部分是白的、没播的压暗**，中间一根**蓝色播放头**；走带行是
  **时间读数 + 白色圆播放键 + 下载键**（文件从卡上直接存，轨道上就不重复给「保存」）。
  声音播完时播放键自己回到「▶」（浏览器放完后 `paused` 仍是 false，得单独听这一下）。
  同样在卡片上，Agent 够不着，只能告诉用户点哪个。
- **同一主体，另一个机位。** 多角度工具让模型换个机位重出，主体的特征、材质和配色
  保持不变。
- **切九宫格。** 宫格切分把一张图切成 N×M 块，每块一个节点。
- **把片子读回来。** 视频接进 `video2text` 模式的文本节点：provider 逐镜头读，文本
  模型写出能做出这条片子的提示词。**读之前片段会在本机压小**（超过 2MB / 12 秒 /
  1280px / 24fps 就重编码，需要本机有 ffmpeg；超过 12 秒的片段只读到前 12 秒）——
  provider 读的是压小后的那份，所以粗一点的片段也能读出来。

## 跑的时候

`canvas_run` 只是把这件事交给页面就返回了 —— 图还没好。之后用 `canvas_read` 看那张
生成卡，**节点的状态才是真的**（`success` / `error` / 还在跑），产物就在它的
`metadata.output` 里。

**慢调用一次只跑一个。** 图片、语音、音乐、视频提交会排队，因为机器一次只给得起一个
窗口。一起要两个不会都快，第二个会在日志里说它等了多久。因为窗口被拒的那次回来说的是
「结果未知」—— 调用可能已经到了 provider，也可能已经扣了费，**不要自己重试那一次**。

**批量只对图片、语音、音乐有效**（一次 2/3/4/6/8 张）。视频一个片子一个任务，文本
一轮一个回复，都不批量。

**页面是唯一写者。** 页面拿着画布时，改动交给页面执行；没人看着时运行时自己执行。
Agent 读到的画布，就是用户看到的画布。

**`canvas_remove_node` 撤不回来**，连在上面的线也一起去。不要拿它去「整理」用户
正在做的画布。

## 画布上可能有别的东西

- **多张画布时先确认画布 id。** `canvas_add_node` 不给 id，就加到**最近修改的那张**
  —— 可能不是用户说的那张。`canvas_list` 一次就能看到所有画布。
- **位置只是初值。** 给的 x/y 是起点，页面会自己重排（谁压到谁谁让开），但画布上
  节点已经很多的时候，给一个空着的位置。
- **素材没了的时候**，那张卡会标「素材已不在」，这次请求会**少带那一份**继续
  跑 —— 不是模型坏了。把少了哪一份告诉用户。

## 模型的限制

参数跟着选中的模型走：模型不提供的时长，菜单里根本没有。请求里破了 provider 的硬
规则（参考集合至少要有一件、音频参考不能单独来、参考一共超过九张图或十二项），会在
发出去之前就带着理由被拒。

**图片节点走的是 MiniMax-H3-Image（Image 3.0）**：一次最多 **16 张**参考图，提示词里
按 `图1`、`图2` 点名；清晰度三档 1K / 2K / 4K，**默认 4K**；画幅默认自适应
（`自适应`），画面跟着提示词走。

**H3 的参考集合（图 + 视频 + 音频）是同一个请求**：模式是「参考生视频」，卡片上的三个
口（图、视频、音频）都往同一组 `reference_*` 里送，最多 12 件。要让模型跟着一条视频走，
就把视频接到那个口上，提示词里按 `@视频N` 点名它 —— 不用换成别的模式。

**带音轨的视频要 MiniMax H3**，而 H3 走账户余额 —— 账户没开「按量自动扣费」，
provider 会直接拒。Hailuo 走 Token Plan，但是静音的。

## 卡片长什么样

- **条分两行：模式一行，值一行。** 卡下的条**上面一行只放下拉**（写着这个节点要
  干什么：文本生成 / 提示词增强 / 图生文 / 文生视频）；**下面一行**是模型按钮
  （写着当前模型名）、一枚摘要芯片（`16:9 · 2K`，只说画幅和清晰度）、数量芯片
  （`× 1`），**「生成」在下面一行的最右边**。点开摘要芯片，浮层里是**比例格子**
  （每个比例画成自己的形状）、**清晰度分段**（1k / 2k / 4K）、时长、音色、情绪。
  参数本身还在 `metadata` 里，Agent 改 `metadata` 一样生效。
  **每颗芯片开自己的浮层**：数量芯片开的是只有数量的那一层（标题「生成数量」，
  只有芯片那么宽，不压着卡片），同一个选项不会在两处出现。**打开的芯片自己会亮**，浮层关掉就暗回去。
  文本节点没有芯片，但条里的模式下拉一直在——切到「提示词增强」，模板下拉就出来。
- **卡片只留素材，浮层选中才出来，而且分上下。** 卡**上方**是轨道：工具坞、
  **「保存」**（把素材存到本机）、输入卡的入口；卡**下方**是操作面：提示词编辑器和
  参数条。两边都是选中才出现；没选中时卡片上只有素材（跑出图的卡上是那张图，
  还没跑过的是一个空框）。
  给用户指路时说「选中这个节点就能改」，别让他去找不存在的按钮。
- **卡是素材的相框。** 用户拖过尺寸的卡，图按自己的比例铺满卡的宽度，卡的高度跟着图走：
  拖大卡就是放大图，不会剩一圈灰边。没拖过的卡是围着素材长出来的。
- **提示词横着写。** 装提示词的操作面是**一页宽**（620px，窗口窄就收窄），一行字横着排，
  不再顺着一条窄柱往下淌；**框高固定**，提示词再长也只在框里滚轮，操作面不会越撑越高。
- **输入卡的入口按有没有素材换。** 空的时候上方只有一颗「⇪ 上传图片」胶囊，
  没有工具坞；有了素材，上方是工具坞 + 「保存」+ 一颗「⋯」，菜单里是
  换个素材 / 复制素材 / 移除这个素材。
- **卡片只有一根发丝线，没有实心圆点，卡面也不写字，而且没有卡头。** 边框不随状态染色，
  卡面上没有类型、没有标题、没有状态，也没有插槽条；卡头整个没有：没有图标、没有「已选」、
  没有「＋」手柄、没有铅笔、没有 ✓ 记号。**状态由卡面自己说**：出图了是成功，出了错是那张
  带四个按钮的失败卡，还没跑是那个写着「还没有产物」的空框。图片不带自己的框，
  插槽和端口是空心细环，装了东西才填实。
  别再往卡片上加实心色块、珠子、文字标签、插槽条或卡头图标。
- **卡上方只浮工具坞。** 工具坞，加末尾那几颗小按钮。**没有提示浮层，也没有插槽胶囊**：
  能进什么、出什么，卡边的端口已经说了；改名在卡片自己的右键菜单里。
- **模型列表和参数浮层朝上弹。** 从卡下的条里往上弹，盖住的是卡片而不是空画布；
  放不下才往下。模型浮层标题是「在线模型」，参数浮层里有「比例」和「清晰度」两段。
- **操作面被挡住时自己翻到卡上方。** 下方没有空画布时，面板翻到卡片上面；平时选中卡片，
  面板还是在下面。卡上不再有翻上去的按钮。
- **失败是一张带四个按钮的卡**：重试 / 取消 / 删除 / 上报。上报会把节点标题、ID
  和错误原因复制到剪贴板 —— 用户要报障时让他点这个，别让他手抄。
- **音频卡是两段式。** 上面一条波形带（播过的白、没播的压暗，中间一根蓝色播放头），
  下面一条走带行（时间读数 + 白色圆播放键 + 下载键）；**卡外上方不挂文件名**。
  别再把波形画成铺满整卡、也别把播放键压在波形正中。
- **下一张卡是手工连出来的。** 卡片上没有「＋」手柄了：加节点走添加菜单，连线靠拖端口。
  Agent 要给用户「下一步」时，给的是同一张节点表——端口落在哪儿，是那张节点真有的口。
- **编组的成员按包含关系算**：框里面的卡就是成员，没有名单可读。Agent 读画布时
  看到的分组节点，它的成员得自己按位置算。

## 开始

用户按名字打开画布（「打开节点画布」/「open the node canvas」），或者 Agent 替他打开。
改任何东西之前先用 `canvas_list` 和 `canvas_read` 读一遍画布，**告诉用户画布上已经
有什么**，而不是再搭一份。
