# H3-Image-Executor（`h3-image-executor`）

[English](README.md)

一个把一句话需求跑成经过校验的 4K 图片的 Mini App。你描述画面，它负责检索参考图、规划分镜、
生成、看图评审、色偏校正、有限次修正、选优，最后交付图片和一份验收报告。

![一次四张图任务完成后的面板：需求、折叠的过程详情，以及带预览、分享和公开链接按钮的交付图](docs/dashboard.jpg)

它围绕 **H3-Image** 生成接口构建。该接口不属于 MiniMax 开放平台的公开图片接口，因此在使用前
你需要自备 H3-Image 的接口地址和 Key，详见[配置接口](#配置接口)。

## 它做什么

- **先规划再动笔。** 规划节点把一句话拆成分镜：每张图一份规格，各自的画幅、硬约束和偏好。
- **自己找参考图。** 当画面里的主体必须长成特定样子时，它会去检索参考图、下载，并判定候选能不能用。
- **多图锁定角色外观。** 多图任务会先生成一张角色设定图，并把它绑到每一张图上作为参考，
  避免同一个主体画到一半变成另一只。
- **看图评审。** 每张候选都由视觉模型按约束逐条核对，而且评审看不到送进模型的那段 prompt，
  不会被 prompt 说服。
- **量色偏。** 偏红由程序实测判定而不是靠眼睛看，判偏红的图会重画而不是直接交付。
- **有限次修正。** 最多 5 轮；连续 2 轮没改善就换改法；连续 3 轮提前收手；
  内容安全审核拒绝会立即停止，不再重试。
- **跨图对比。** 所有图出完后拼一张并排对比图，判断「同一个主体是不是同一个东西」。只报告，不自动重画。
- **交付验收报告。** 每次交付都带一份 `report.json`：逐图判定、每次生图的 `request_id`、成本，
  以及它没能验证的部分。

## 环境要求

- MiniMax Code 3.1.6 或更高版本（本应用声明了 `toolAccess` 与 `agentAccess`）。
- 一个 H3-Image 接口地址和 API Key。

## 安装

1. 把整个目录（含隐藏的 `.minimax-plugin`）复制到 MiniMax Code 的插件目录，目录名为
   `h3-image-executor/`（默认是 `~/.minimax/plugins/h3-image-executor/`），也就是清单最终位于
   `~/.minimax/plugins/h3-image-executor/.minimax-plugin/plugin.json`。
2. 重启 MiniMax Code，确认插件已启用。
3. 对 Agent 说「打开 H3-Image-Executor」，或从插件列表里打开。

## 配置接口

本应用**不内置任何默认接口地址**。在配置之前，侧边栏底部的引擎状态会显示「未配置生图接口」。

点击那行打开设置面板，填写：

| 字段 | 含义 |
| --- | --- |
| API Key | 你的 H3-Image Key，只会发往你配置的接口地址。 |
| 接口地址 | H3-Image 接口的基础地址，必须以 `https://` 开头。 |

Key 写入 Host 为本插件创建的私有 `dataDir` 下的 `settings.json`，权限 `0600`。它不会写进包体、
不会打进日志。保存下来的 Key 不会回传给页面：页面只能拿到前 6 位和 Key 长度。

也可以在 shell 里导出后重启 MiniMax Code：

```sh
export MINIMAX_API_KEY="..."
export MINIMAX_BASE_URL="https://..."
```

`MCODE_API_KEY` 也会被当作 Key 读取；进程环境变量里两个都有时以 `MINIMAX_API_KEY` 为准。
`H3_IMAGE_MODEL` 可以覆盖模型名，默认是 `MiniMax-H3-Image`。

解析顺序是：页面里保存的配置 → 进程环境变量 → `~/.zshrc` / `~/.zprofile` /
`~/.bash_profile` / `~/.profile`。**页面优先**，你在页面上明确填过的值不会被别处遗留的环境变量覆盖。

## 使用

在输入框里写下你要的图，回车发送。应用会跑完整条链路并交付图片和报告。几点值得知道：

- **默认输出 4K。** 除非你指定画幅，否则由规划决定。
- **每次生图都会显示 `request_id`**，在过程时间线上是一个 `req …` 小标签，点一下复制完整值；
  反馈问题时请附上它。
- **失败的图会说清原因。** 接口报错（包括内容安全审核拒绝）会带着原始报文出现在交付区，
  而不是一句没有下文的「0 张」。
- **可以在同一会话里追问。** 再发一条消息是在已交付的图上继续改，而不是从头再来。
- **历史在侧边栏。** 每条可以重跑或删除；删除是把会话移进 `dataDir` 下的 `sessions/.trash/`，不是抹掉。
  应用从不清空这个目录，要释放磁盘空间请自己删除里面的内容。
- **停止任务。** 「停止」按钮会中止这个会话的 Agent 轮次，并在下一步结束任务。已经发给接口的
  生图请求仍会跑完，但之后不会再启动新的步骤。
- **也可以直接在聊天里说。** 启用插件后，在会话里说「画一张…」会把需求交给本应用，
  而不是在聊天里另生成一张图；你点名要用别的工具、或者说不想用这个面板时除外。随包发布的
  `h3-image-executor` Skill 会引导 Agent 用 `?prompt=…&auto=1` 打开面板，页面自己填好输入框并提交。

### 启动参数

面板会从自己的 query string 里读这些参数。Agent 就是靠它把需求递进来的，你也可以自己用来做深链：

| 参数 | 含义 |
| --- | --- |
| `prompt`（或 `q`） | 需求原文，逐字使用。 |
| `auto` | `1`（默认）填入并直接提交；`0` 只填入，等你自己按发送。 |
| `session` | 会话 ID，例如 `20261109-877482`。带上表示「接着调那一张」，不带表示开新的一张。 |
| `len` | 可选。发送方数出来的 `prompt` 字符数。和实际收到的对不上时，页面会提示需求可能在传输中损坏，但仍然提交。 |

页面读完就立刻把这些参数从地址栏抹掉，所以刷新不会把同一条需求再提交一遍。
如果还没配接口，需求会填进输入框但不会自动提交，输入框上方会说明原因。

## 已验证环境

- macOS 15.0.1（Apple Silicon）上的 MiniMax Code 3.1.12-preview.5165

用当前版本（1.8.1）在该环境下验证过：发布公开链接（含页面上的 `website_deploy` 确认）、在聊天里说
画图需求会交给面板。用更早的版本在该环境下验证过：单图与多图任务端到端跑通、参考图检索与下载、
角色设定图生成与跨图对比、有限次修正循环、色偏实测、运行时重启后会话恢复、删除与重跑、分享页生成、
失败信息透传。

只用模拟 Host 的自动化测试（Node 服务，加上无头 Chrome 里的页面）验证过、没有在 MiniMax Code 里实测的：
当前版本的端到端出图、分享页里 2048px 的大图、「停止」按钮、关闭 `session.run` 或 `tool:call` 后的提示、
问卷、Host 重新加载页面后的视图恢复。未验证：Windows、除上述版本外的 MiniMax Code、以及开发时所用
之外的任何 H3-Image 接口。

## 数据与访问

**读取包体之外的文件**

- `~/.zshrc`、`~/.zprofile`、`~/.bash_profile`、`~/.profile`——按纯文本读取、从不执行，仅在你没有
  在页面里配置时，用于查找 `MINIMAX_API_KEY`、`MCODE_API_KEY` 和 `MINIMAX_BASE_URL`。这依赖 shell
  配置的文件布局，不属于任何已公布的契约。
- 你通过文件选择器挑的参考图。

**写入的文件**

- 应用保存的所有内容都写在 Host 提供的 `dataDir` 下：`settings.json`（权限 `0600`）、
  `sessions/<id>/`（规划、图片、预览、参考图、评审拼图、交付物、报告、分享页 `share/index.html`
  及其内嵌大图的缓存 `share/large/`、`session.json`）、`refcache/`（下载的参考图，以及保留一天的下载失败记录）、`sessions/.trash/`
  （已删除的会话）。
- 两个 JSON 状态文件——`settings.json` 和 `sessions/<id>/session.json`——是原子写入：同目录临时
  文件再 `rename`。图片和 HTML 文件直接写。
- `dataDir` 之外只有两处会写文件：
  - 发布轮次（见「调用的工具」）会把分享页复制到本 Mini App 自己的 Agent 工作目录下的
    `h3-share-publish/index.html`，因为 `website_deploy` 只接受这个目录里的路径。每次发布都会覆盖它。
  - 随 `h3-image-review` Skill 发布的 `h3-review` 命令行工具，在 Agent 运行它时写 PNG 看图材料：
    `sheet` 写在输入图旁边，`refs` 和 `grid` 写在当前工作目录，或者写到 `-o` 指定的位置。
    应用自己从不运行它。
- 页面在自己的浏览器存储里保存视图状态：侧边栏是否收起；以及每次页面被隐藏时记下的当前会话 ID、
  输入框里还没发出去的文字（最多 4000 字）和已选但未发送的参考图张数，这样 Host 重新加载页面后能恢复。

**网络**

- 你配置的 H3-Image 接口。它会收到你的 Key（作为 bearer token）、你的 prompt，以及你提供的参考图。
  没有默认值——就是你填的那个。
- 该接口返回的图片地址，应用会从那里下载图片。
- 参考图检索（见「调用的工具」）找到的图片地址，以及规划轮次写进规划里的图片地址：可能是任何第三方
  网站，`https` 或 `http` 都有。应用只下载这些图片；检索查询本身经由工具发出，不是本应用直接发出。

本应用拒绝从 `169.254.0.0/16`（云主机元数据服务所在的链路本地段）以及 `0.0.0.0` 这类通配地址
下载图片，跟随每一次重定向之前都会重新检查一遍地址。对检索工具给出的图片地址，还会拒绝 localhost
和私有段（`10.*`、`172.16-31.*`、`192.168.*`、`100.64-127.*`、`fc00::/7`），包括解析到这些地址的
域名：第三方的检索结果不应该让应用去读你自己网络里的东西。对你的接口返回的图片地址、以及按你的需求
写进规划里的图片地址，私有段和 localhost 仍然允许，因为你的接口本身可能就在内网。每次下载都有上限：
参考图 25 MB，生成图 100 MB。

**启动的进程**

只有剪贴板命令，没有别的。每一条都是参数固定、不拼 shell、2 秒超时、输出有上限。

- **读**——MiniMax Code 禁止 Mini App 页面读剪贴板，所以设置面板里的「剪贴板」按钮会让 Node 服务
  调一次本机的粘贴命令：macOS 是 `pbpaste`，Windows 是
  `powershell.exe -NoProfile -NonInteractive -Command Get-Clipboard`，Linux 是 `wl-paste` 或
  `xclip`，上限 8 KB。读到的内容只用于回填输入框：不写日志、不落盘，而且只有「像 Key」或
  「像 `https://` 接口地址」时才会回传给页面。
- **写**——页面先用浏览器剪贴板复制（`navigator.clipboard.writeText`，不行再用
  `document.execCommand('copy')`）。这两条都要求面板处于聚焦状态，而面板经常没有焦点，所以 Node 服务
  也可以调本机的复制命令：macOS 是 `pbcopy`，Windows 是
  `powershell.exe -NoProfile -NonInteractive -Command Set-Clipboard -Value ([Console]::In.ReadToEnd())`，
  Linux 是 `wl-copy` 或 `xclip`，上限 2 KB。它只在两种情况下执行：你发起的一次发布完成时自动执行
  一次，把新的公开链接放进剪贴板；以及会话已有公开链接、你点「分享」而页面没能复制时。Node 服务只接受
  单行的 `https://<name>.space.mcode.cn` 地址，其余一律拒绝——所以这个接口没法被当成「往你剪贴板里
  写任意内容」的后门。

加载时、定时轮询时、保存时都不会启动任何进程，除此之外不会启动任何子进程。

**Agent 轮次**

本应用声明 `agentAccess: ["session.run"]`，会运行 Agent 轮次来做规划、评审和修正。这些轮次运行在
你 MiniMax Code 会话所配置的模型服务上，因此你的 prompt 原文、参考图以及生成出来的图本身都会送到
该模型服务，用于规划、评审、修正和选优。这些轮次可以读写文件、执行 shell 命令、调用 MCP 工具，
均受你的权限规则约束。每一个工具权限请求都会展示在页面上由你决定，包括下面「调用的工具」里说的
发布轮次发起的 `website_deploy` 请求；应用从不替你放行。它自己只会拒绝发布轮次发起的其他工具请求。
如果你在插件详情里关闭了 Agent 权限（`session.run`），任务会停下，页面会说明去哪里重新打开。
它没有声明 `session.read`，读不到你的其他会话。

**调用的工具**

本应用声明 `toolAccess: ["call"]`，只调用一个工具：已安装工具里第一个名字包含 `search_images`
的工具。在测试环境里它是 `connector__matrix__search_images`，即 `matrix` Connector 的
`search_images` 工具。它收到的是规划里的主体名，以及一句说明要找什么样的图，返回图片地址。每次调用
都走你的权限规则；规则为「询问」时，应用会在第一次检索前弹出 Host 的确认框，请你始终允许这一个工具。
如果你在插件详情里关闭了工具调用（`tool:call`），任务会在没有检索参考图的情况下继续，页面会说明原因。

「发布公开链接」按钮是另一回事，值得单独说清楚：它会起一个 Agent 轮次，这轮唯一的任务是调用
Host 的 `website_deploy` 工具，把自包含分享页发布到一个公开的 `https://<name>.space.mcode.cn`
地址，**任何拿到链接的人都能打开**。页面里包含：你的需求和追问、你上传的或应用在网上找到的参考图、
其余检索结果的缩略图、规划、所有候选图和交付图的缩小版、每张交付图一份长边 2048px 的大图（点开时显示）、
评审拼图、应用发给模型的完整提示词和模型的回复，以及带 `request_id` 和成本的执行记录。大图总量上限 4 MB，
超出的交付图点开时仍是预览大小。你点了这个按钮、并且在页面上对出现的 `website_deploy`
请求点了「允许一次」之后，才会真正发布。按钮下面常驻一行提示，说明任何拿到链接的人都能打开，以及页面包含
哪些内容。写盘前，本机路径会被替换成占位符：会话目录和插件的 `dataDir` 保留其后的相对部分，用户
主目录下的其他路径、以及 `/Users/` 或 `X:\Users\` 下的路径整段替换。发布轮次的其他工具请求一律
拒绝；如果它发起提问，整轮直接中断。

**随包发布的 Skill**

- `h3-image-executor` 让聊天里的 Agent 把画图需求交给本应用，而不是用别的生图工具；你点名要用别的
  工具、或者说不想用这个面板时除外。你问起某次跑完的任务时，它会让 Agent 去读本插件数据目录下的
  `sessions/<id>/session.json`。Skill 并不知道 MiniMax Code 把这个目录放在哪里，所以找到它依赖未公开的
  目录布局。
- `h3-image-review` 告诉 Agent 在你要它亲自看生成图时，怎么运行随包的 `h3-review` 工具（见「写入的文件」）。

**设备使用**

不使用麦克风、摄像头和系统通知，未声明任何 `deviceAccess`。
不读取你当前所在的 MiniMax Code 页面，也不读取浏览器历史。页面只在你点击复制控件时（`req …` 标签，
或已有链接时的「分享」）以及你发起的发布完成后写一次剪贴板；上面那些剪贴板命令跑在 Node 服务里。
应用只看得见它自己的面板。

## 已知限制

- 角色设定图能改善一致性，但不保证。设定图与故事图之间姿势或画幅差异大时仍会漂移。
- 内容安全审核拒绝是确定性的，所以应用在第一次被拒时就停下，不再重试。请修改需求本身后重新发送。
- 参考图检索依赖检索工具，可用性随它而定。工具拒绝或检索失败时，这个主体就没有检索到的参考图，
  请自己上传一张。
