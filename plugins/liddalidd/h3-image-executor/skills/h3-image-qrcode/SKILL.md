# 把图里的假码换成真码

## 先记住三条

1. **生图模型画不出能扫的二维码。** 它画的只是长得像码的黑白方块。要让码能扫，就用这里的 `fix` 贴真码，
   不要让生图模型「画准一点」，也不要自己写编码或贴图脚本。
2. **码里放什么只能来自用户。** 从用户原话里逐字复制链接、文字或号码，一个字符都不改：不补全、不缩写、
   不换成你觉得对的网址。用户没说放什么，先问一句「二维码里要放什么链接或文字？」，不要自己编。
3. **「能扫」只认工具的扫码结果。** `fix` 退出码为 0、输出 JSON 里 `ok: true`，才能告诉用户「已经换成能扫的码」。
   不要凭看图下结论。

## 什么时候用

| 场景 | 做法 |
| --- | --- |
| 用户给了一张图（任何来源），说码扫不出、或者要把码换成某个链接 | `fix` |
| 用户问一张图里的码能不能扫、扫出来是什么 | `scan` |
| 想知道图里有几枚码、在哪、多大（包括扫不出的假码） | `locate` |
| 用户要一张单独的二维码图 | `make` |

**H3-Image-Executor 面板里出的图不用这个工具。** 面板流水线出图后会自动贴真码并扫码验证；
要给装饰码补内容或换内容，带上会话 ID 把用户的话递进同一个面板会话（见 `h3-image-executor` skill），
面板会直接在原图上换码。不要用这个工具去改插件数据目录里的文件。

## 工具位置与用法

工具随 H3-Image-Executor 插件发布，零第三方依赖（扫码用同包 `miniapp/node/vendor/jsqr` 里的 jsQR，Apache-2.0）：

```bash
node "<PLUGIN_ROOT>/miniapp/node/tools/h3-qr.mjs" <子命令> [参数]
```

| 子命令 | 用途 | 成功输出 |
| --- | --- | --- |
| `fix <图片> --content <内容> [-o 输出]` | 把图里的码换成真码，从输出文件扫码验证 | `{ok,out,changed,format,results}` |
| `fix <图片> --content-file <文本文件> [-o 输出]` | 同上，内容从 UTF-8 文本文件读（只去掉末尾一个换行） | 同上 |
| `scan <图片>` | 扫出图里所有能扫的码 | `{width,height,count,codes:[{data,version,corners}]}` |
| `locate <图片>` | 找出所有码的位置，包括扫不出的假码 | `{count,regions:[{scannable,data,modules,modulePx,corners,quietModules}]}` |
| `make --content <内容> [-o 输出.png] [--ecl L\|M\|Q\|H]` | 单独生成一张二维码 PNG，并自扫确认 | `{ok,out,version,ecl,modules,scanned}` |

- 成功时 stdout 只有一个 JSON 对象，退出码 0。
- 用法或文件错误：stderr 给原因，退出码 1。
- `fix` 换码后验证没通过：stderr 第一行是原因、第二行是 JSON，退出码 2，**不写输出文件**。
- 内容里有引号、`$`、反斜杠、换行时，先把内容原样写进一个文本文件，再用 `--content-file`，免得被 shell 改掉。
- 图里有多枚码时，`--content` 按图里从上到下、从左到右的顺序给多次；只给一条时换图里最大的那枚。

## 标准流程（换码）

1. 用户没给内容就先问；给了就逐字照抄。
2. 跑 `fix`。不带 `-o` 时输出写在原图旁边：`<原名>-qr.<扩展名>`，重名时加 `-2`、`-3`。**永远不覆盖原图**。
3. 退出码 0：告诉用户输出文件路径，以及扫码实测出的内容（就是 `results[].content`）。
4. 退出码 2：把原因如实告诉用户（见下表），不要说「已修好」。

## 没换成的原因和怎么办

| 原因 | 说明 | 建议用户怎么做 |
| --- | --- | --- |
| 没在图里找到二维码 | 找不到三个角的回字形定位方块：码被遮挡、太斜、做成了艺术化图案，或者图里根本没有码 | 换一张码画得规整的图；重新生成时要求「正对镜头、白底黑块、三个角的定位方块完整、四周留白」 |
| 图里的二维码太小，装不下这段内容 | 贴上去每个模块不到 4 像素，扫码靠运气 | 换更大的码，或者把内容换成短链接 |
| 贴上真码后扫不出来 | 透视太斜、码被局部遮挡、四周没有留白 | 同「没找到」 |
| 内容太长，生成不了二维码 | 超过二维码容量（字节模式最多约 2900 字节） | 换成短链接 |

## 工具做了什么（用户问起时照实说）

- 定位：先扫一遍能扫的码，再找三个角的定位方块（1:1:3:1:1 的黑白比例），沿定位方块的外边缘拟合四条边，得到透视四角。
- 贴码：按内容生成标准二维码（纠错等级默认 M，内容太长或码太小时退到 L，码区放得下时自动提到 Q 或 H），把原来的码抹成浅色，
  按透视画进去；颜色取自原图的浅色和深色区域并跟着原来的明暗走；四周留至少 3 个模块的白边，不够时把码缩小一点让出来。
- 验证：输出文件写出之前，先按最终格式编码（原图是 PNG 输出 PNG，否则输出质量 93 的 JPEG），再从这份字节重新解码，
  三种裁切范围下各扫「近看」和「远看」（每个模块约 2 像素）一次；近看、远看都至少两次扫出要放的内容才算通过，
  任何一次扫出别的内容判不通过。
- 只认正色码（深色码印在浅底上）：反色码多数手机扫不了，工具也不按反色验证。
- 码里不加 ECI 声明，文字按 UTF-8 写入；微信和系统相机都按 UTF-8 解。
