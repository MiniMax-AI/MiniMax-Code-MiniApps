# 组图和帧拼成 GIF

## 先记住三条

1. **生图模型一次只出一张静态图。** 要动起来只有两条路：让模型画一张分格的组图，切开按顺序播（`grid`）；
   或者静态图由模型画，会动的部分由你写程序一帧一帧算出来（`frames`）。不要让生图模型「画一个 GIF」。
2. **H3-Image-Executor 面板里出的图，在面板里做。** 面板交付的组图，用户说「把这组图变成 GIF」时带会话 ID 把原话
   递进同一个面板会话（见 `h3-image-executor` skill），面板会切格拼 GIF，相邻两格之间补过渡格（组图不重画）；
   这个工具不生图，拼出来是一格一格地切换；要连贯的动作（眨眼、挥手）
   也交给面板，它会按参考图一帧一帧改。这个工具给面板以外的图用：用户自己给的组图、别的工具画的图、你写程序画的帧。
   面板交付的是几张单独的图（四张一组的漫画），用户要按顺序拼成 GIF 时，面板会说让你来拼：从会话的 `session.json` 里
   `turns[].delivery.items[].file` 找到交付文件（在会话目录的 `deliver/` 下），用 `slides` 拼，`-o` 写到工作区里。
   不要把输出写进插件数据目录，也不要改那里的文件。
3. **「做好了」只认工具的结果。** 退出码 0、输出 JSON 里 `verify.ok` 为 true 才算做成；再 `read` 一下帧拼图（`sheet`），
   看格子切得对不对、顺序对不对。读 GIF 文件本身通常只看得到第一帧，不能代替帧拼图。

## 什么时候用

| 场景 | 子命令 |
| --- | --- |
| 一张分格的组图（任何来源）要变成 GIF | `grid` |
| 只想把组图切成一格一格的 PNG，再自己加工 | `split` |
| 几张单独的图按顺序播（四张一组的漫画、一组表情） | `slides` |
| 你写程序画好了一组帧 | `frames` |
| 一张图里有个绕中心转的东西（加载圈、图标、齿轮），要让它转起来 | `spin` |
| 看一个 GIF：几帧、每帧多久、循环没有、首尾接不接得上 | `check` |

## 工具位置与用法

工具随 H3-Image-Executor 插件发布，零第三方依赖：

```bash
node "<PLUGIN_ROOT>/miniapp/node/tools/h3-gif.mjs" <子命令> [参数]
```

| 子命令 | 用途 | 成功输出 |
| --- | --- | --- |
| `grid <组图> [--rows R --cols C \| --count N] [节奏参数] [-o 输出.gif] [--sheet 帧条.png]` | 找格子、切开、对齐、按节奏拼成 GIF，读回核对 | `{ok,out,sheet,width,height,bytes,frames,durationMs,loop,grid,framing,timeline,verify}` |
| `split <组图> [--rows R --cols C \| --count N] [--no-align] [-o 目录]` | 切成同样大小的 PNG：`01.png`、`02.png`…… | `{ok,dir,width,height,grid,files}` |
| `slides <图1> <图2> … [节奏参数] [-o 输出.gif] [--sheet 帧条.png]` | 几张图按顺序拼成 GIF，按第一张的画幅统一大小 | 同 `grid`，另有 `sources`、`mode` |
| `frames <帧1> <帧2> … \| --dir <目录> [--frame-ms 100 \| --delays 310,60,…] [--once] [--edge 长边 \| --scale 倍数] [--dither none\|ordered] [--colors N] [--stabilize N] [--fit] [-o 输出.gif] [--sheet 拼图.png]` | 一组帧编码成 GIF，读回核对，看接缝。默认每帧 100 毫秒，按帧的原尺寸写，长边超过 1024 的缩到 1024，不放大 | `{ok,out,sheet,width,height,bytes,input,frames,delays,durationMs,loop,colors,dither,seam,notes,verify}` |
| `check <GIF> [--frames N] [--loop \| --once] [--ms 总毫秒] [--sheet 拼图.png]` | 读一个 GIF，按给的预期核对 | `{ok,width,height,bytes,frames,delays,durationMs,loop,steps,seam,notes,problems,sheet}` |
| `spin <图片> [--center x,y] [--radius r] [--steps N \| --frames N] [--ccw] [--frame-ms N] [--fade \| --cut] [--no-refine] [--once] [--edge 长边] [-o 输出.gif] [--sheet 帧条.png]` | 绕圆心把图里的一块圆盘转起来 | `{ok,out,sheet,width,height,bytes,frames,written,durationMs,loop,steps,direction,transition,frameMs,center,radius,moved,verify}` |

节奏参数（`grid`、`slides`）：

| 参数 | 说明 |
| --- | --- |
| `--order 1,2,3` | 播放顺序，写格子编号（从上到下、从左到右数）；没写的格子不放 |
| `--frame-ms 700` | 每格停多久，默认 700 毫秒 |
| `--first-ms`、`--last-ms` | 第一格、最后一格停多久，默认是每格的 1.5 倍、2 倍 |
| `--hold 6:1500` | 第 6 格停 1500 毫秒，可以写多次 |
| `--pingpong` | 来回播（1→6→2，再接回 1） |
| `--once` | 只播一遍（默认循环） |
| `--fade` | 两格之间叠两帧渐变（默认直接切换） |
| `--bounce` | 切换时弹一下：新的一格先放大 3%，0.08 秒后落回原大小。默认不弹：整幅画面会跟着放大再落回，各格对齐得再准，每次切换也会跳一下 |
| `--edge 768` | GIF 长边，默认 768 |
| `--no-align` | 不对齐各格（`grid`） |

- 成功时 stdout 只有一个 JSON 对象，退出码 0。
- 用法、文件错误、切不出格子：stderr 给原因，退出码 1。
- 写出去的 GIF 读回来核对没通过：stderr 第一行是原因、第二行是 JSON，退出码 2，**不写输出文件**；`check` 的预期没对上也是退出码 2。
- **永远不覆盖输入文件。** 不带 `-o` 时写在输入旁边：`grid` 写 `<组图名>.gif`，`slides` 写 `<第一张>-slides.gif`，
  `frames` 写在帧目录旁边 `<目录名>.gif`；重名时加 `-2`、`-3`。帧拼图默认写在 GIF 旁边：`<GIF 名>-frames.png`。
- 输入只认 PNG、JPEG（GIF 取第一帧）。透明背景会铺成白底：GIF 只有全透明和不透明两种，这个工具不保留透明。

## 组图 → GIF（grid）

1. 跑 `grid`。默认按分隔线或留白自动找格子，从上到下、从左到右排顺序。
2. 退出码 1、说没找到分隔：多半是白底贴纸这种格子之间什么都没有的图。看一眼图，用 `--rows 2 --cols 3`
   （或 `--count 6`）说明几行几列，按等分切。用户说过几格就照用户说的给。
3. 退出码 0：`read` 帧条（`sheet`），核对格子数、顺序和每格的画面，再把 GIF 路径告诉用户。
4. 用户要调：慢一点加大 `--frame-ms`；结尾多停一会儿用 `--last-ms`；去掉某一格用 `--order` 写出要留下的格子；
   要柔和一点用 `--fade`（两格差得多时叠出来是半透明的虚影，先告诉用户）；用户点名要切换时弹一下才加 `--bounce`。

输出里 `grid.panels` 是每格在原图里的位置，`grid.method` 是怎么切的（`line` 分隔线 / `gutter` 留白 / `free` 格子大小不一 / `even` 等分：格子之间没有清楚的分隔，或者按你给的行列），
`framing.offsets` 是对齐时每格挪了多少像素（模型在每一格里画的主体位置差一点，原样播主体会一跳一跳的）。

文件大小：一张六格的 Q 版表情组图拼成长边 768 的 GIF 是 388 KB；细节多的二次元组图（屏幕上一整面 K 线）是 909 KB。
加 `--bounce` 每格多一整帧，文件大约大一倍。用户嫌大，减小 `--edge`。

## 让图里的东西转起来（spin）

1. 看图：转动的东西的中心在哪（`--center x,y`，画面宽、高的比例），要转的范围多大（`--radius`，短边的比例，要盖住整个转动的东西；
   给小了程序会按画面内容放大）。
2. 圆环上等距的点、辐条、格子（亮点一格一格跑）用 `--steps N`，N 就是点数：每帧转一格，暗的点正好落回原位、看起来不动，
   程序还会在给的圆心附近找「转一格之后和自己最重合」的位置；默认每格 80 毫秒、两格之间叠一帧渐变（`--cut` 不要渐变）。
   整个东西连续转用 `--frames N`（一圈 N 帧，默认 24、每帧 50 毫秒），不找圆心，用你给的。`--ccw` 逆时针。
3. 转的是圆心周围一整块圆盘，里面的背景跟着转、外面不动：圆盘里的背景是纯色或者从圆心往外的渐变时看不出来；有图案的话会看到它在转，
   先告诉用户。输出里 `center` 是程序最后用的圆心，`moved` 是比你给的挪了多少。
4. 只能在画面这个平面里转，硬币翻面、地球自转这种立体的转动做不了。

面板里出的图要转起来，带会话 ID 把用户的话递进面板（「让它转起来」），面板直接转，不用这个工具。

## 程序画帧 → GIF（frames）

做法参考 jungle-adventure、david-voxel-loop 两个例子：静态底图由生图模型画，会动的部分由程序一帧一帧算出来。

1. **底图**：用面板画，或者用用户给的图。程序在底图上叠加会动的东西（小人沿路径走、藤蔓摆动、鸟飞过），
   或者把底图本身拆开重组（雕像碎成粒子再复原、一道扫描线扫过）。
2. **按周期算每一帧**：第 i 帧的相位 `p = 2π·i/N`，位置、角度、亮度都写成 `p` 的 sin/cos，第 N 帧正好回到第 0 帧，
   循环就没有接缝。可以多算一帧第 N 帧，和第 0 帧逐像素比一次（jungle 的做法）。
   有停顿的动作（david：静止 → 碎开 → 复原 → 静止），首尾两帧用同一张图，用 `--delays` 给首尾更长的停留，例如 `--delays 310,60,55,…,115`。
3. **像素风**：在小画布上画（例如 256×256），存帧时不要自己放大，交给 `--scale 2`（最近邻放大，像素不会糊），再加 `--dither none`。
4. **存帧**：每帧一个 PNG，同样大小，文件名带序号（`frame-00.png`……`frame-15.png`），放进一个单独的目录。
   写帧的代码用手上有的：装了 Pillow 就用 Python（两个例子都是）；没有的话用 Node，PNG 编码器用插件自带的：
   `import { encodePng } from '<PLUGIN_ROOT>/miniapp/node/lib/png.mjs'`，`encodePng({ width, height, channels: 3, data })` 返回 PNG 的字节，
   `data` 是按行排的 RGB。
5. **编码**：`frames --dir <帧目录> --frame-ms 80`。默认逐像素写进去（`--stabilize 0`），差一两级的余辉、渐隐也不会丢；
   帧是照片质感、有噪点时可以 `--stabilize 8`，文件小一些。
6. **看结果**：`seam.jump` 为 true，说明最后一帧接回第一帧时会跳一下，回去改帧（最后一帧应该是第一帧的前一步）；
   `notes` 里还会写首尾两帧完全一样、有的帧和前一帧一模一样被并掉、时长被取整到 10 毫秒这类情况。
   最后 `read` 帧拼图（每行 4 帧，16 帧就是 4×4），确认动作顺序。

GIF 的每帧时长以 10 毫秒为单位，输出里的 `delays` 是实际写进去的值。浏览器会把短于 20 毫秒的帧按 100 毫秒播，工具最短写 20 毫秒。

## 工具做了什么（用户问起时照实说）

- **找格子**：在缩到长边 1024 的图上，按列、按行量两种证据：细线（这一列和左右隔几个像素的列都差得多、方向一致，贯穿大部分行），
  留白（整列一个颜色，两边紧挨着贯穿整列的格子边）。逐个假设「等分成 n 格」，在等分位置附近找证据，所有分隔都找得到的假设里
  取格子最多的；先切行，每一行再单独切列，所以上面两格、下面三格也切得开。只有一格的矮行（标题栏）和整格一个颜色的空格子不算。
  切点只贴到等分位置附近贯穿八成以上的线或留白带上；附近没有（格子直接挨着画，没画分隔线）就按等分位置切，
  不贴到格子里面的竖线上（屏幕边框、图表坐标轴、门框）。
- **修边、对齐**：修掉格子边上残留的分隔线、外框和半条留白，只修这些结构，不修格子里的内容。各格居中取同样大小；
  再找每一格相对第一格的平移：只比每格的中上部（左右各去掉 15%、下面去掉 30%，主体的头和脸通常在这里，手和背景每格不一样），
  先在长边 320 的梯度图上粗找（最多挪格子宽高的 4%，明显更贴合才挪），再在长边 960 的图上细调到亚像素。
  格子大小差得多的排法不裁，缩进同一个画幅、四周补底色。
- **编码**：全组一套 255 色调色板（在所有帧上做中位切分），平涂图不抖动，其余用按像素位置固定的有序抖动，同一位置同一颜色每一帧
  色号一样，不会一帧一闪。和上一帧没差别的像素沿用上一帧；和上一帧一模一样的帧并进前一帧的时长。
- **核对**：写完从字节读回来，核对尺寸、帧数、每帧时长、循环，每一帧和要写的画面平均差不超过 6 级。没过就不写文件。
- **接缝**：把各帧缩小、模糊两档以后，比较最后一帧到第一帧的变化和中间最大的一步；大三成以上判为会跳。只数变了多少像素不行：
  小物体挪一步和从画面一头跳回另一头，变的都是两个整圆。
