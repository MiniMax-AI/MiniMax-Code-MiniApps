# H3 生成图评审

## 先记住三条

1. **不要自己写测量脚本。** 尺寸、色偏、锐度、过曝、像素差都有现成命令，直接调。
2. **不要自己裁图拼图。** `sheet` 会把整体、曝光两联、四象限局部放大拼成一张带编号的图，读一次就够。
3. **判 fail 要有证据。** 指不出"在哪一块看到什么"就不能判 fail；拿不准记 uncertain 并放行。

## 工具位置与用法

工具随 H3-Image-Executor 插件一起发布，零第三方依赖（只用 Node 内置 + 自带的 PNG/JPEG 解码器）：

```bash
node "<PLUGIN_ROOT>/miniapp/node/tools/h3-review.mjs" <子命令> [参数]
```

| 子命令 | 用途 | 输出 |
| --- | --- | --- |
| `sheet <图片> [-o 输出.png]` | 生成候选看图材料（7 块带编号） | `{sheet,width,height,layout}` |
| `refs <图片...> [-o 输出.png] [--per-row N]` | 把多张参考图拼成一张带 R1/R2… 编号的对比图 | `{sheet,items}` |
| `grid <图片...> [-o 输出.png] [--per-row N]` | 并排对比多个候选，用于选优 | `{sheet,items}` |
| `stats <图片>` | 尺寸、色彩统计、色偏判定、亮度直方图 | JSON |
| `compare <图片> <父图>` | 相对父图的色彩漂移、锐度变化、平均像素差 | JSON |

成功时 stdout 只有一个 JSON 对象；失败时 stderr 给原因并以非 0 退出。

不带 `-o` 时：`sheet` 写在输入图旁边，`refs` / `grid` 写在当前工作目录。输出路径在返回的 JSON 里。

## 标准评审流程

1. **备料**：对每个候选跑 `sheet`，对参考图集合跑 `refs`。
2. **读图**：用 read 打开每个候选的 sheet 和那张 refs sheet。**只读这些，不要去读原始大图。**
3. **采信程序结论**：`stats` / `compare` 给的尺寸、色偏、锐度、过曝直接当事实，不要用眼睛推翻。
4. **逐条判清单**，然后给结论。

## 看图材料的版式

`sheet` 产出的图自上而下三段，每块左上角有数字标签，可以直接引用编号：

- **1** = 整体预览 → 看构图、主体、氛围、主体数量
- **2** = 暗部提亮（左） → 看暗处有没有藏东西、多余物体、水印
- **3** = 亮部压暗（右） → 看高光有没有溢出死白
- **4 / 5 / 6 / 7** = 局部放大，依次取自左上、右上、左下、右下象限中心 → 看畸形、糊字、接缝、材质、手部

## 判定规则

**hard 项（必须满足）**

- 只有能在材料图上指出一个明确的、看得见的缺陷时才判 `fail`。
- note 必须写清楚：**在哪一块（引用编号）+ 看到什么**。指不出来就不能判 fail。
- 判不准用 `uncertain`，**uncertain 记 pass**，note 写清楚哪里拿不准。
- 常见误判：把"不够惊艳""构图不是我最喜欢的那版""风格还可以更好"写成 fail。这些是 soft。

**soft 项（偏好）**

- 只影响 quality 分（0-10），不影响通过与否。

**一致性核对（真人 / 车型 / logo）**

- 对照 `refs` sheet 判。认识的人一眼能认出才算 pass。
- 但"认不出"必须是**明确的五官/车型特征对不上**，不是"感觉不太像"。后者记 uncertain。

**图内文字**

- 在 4/5/6/7 局部块上看字形。糊成一团、缺笔画、写成别的字 → fail。
- 文字太小看不清 → 先看 `stats` 的尺寸确认是不是分辨率问题，再决定 fail 还是 uncertain。

## 反过度评审

过度打回的代价是整轮重做（几十秒到几分钟），远大于放过一次小瑕疵的代价。所以：

- 工具调用控制在 5 次以内：每个候选的 sheet + 一张 refs sheet，看完立刻给结论。
- 不要为了"稳妥"把 uncertain 写成 fail。
- 不要提清单之外的新要求。清单之外的观察写进 summary，不作为打回理由。
- 不要联网搜索、不要跑统计脚本、不要裁图量像素。
- note 不超过 30 字，summary 不超过 40 字。

## 输出格式

```json
{
  "verdicts": [
    {
      "candidateId": "A-r1-g0",
      "checks": [{ "id": "H1", "result": "pass|fail|uncertain", "note": "第 5 块：右手六指" }],
      "quality": 7.5,
      "summary": "..."
    }
  ],
  "next": { "type": "regenerate|edit|give_up", "candidateId": "...", "prompt": "...", "reason": "..." }
}
```

所有 hard 都通过时，`next` 直接写 `{"type":"give_up"}`。
