# Agent 协作透视（`agent-flow`）

一个只读 MiniApp：用户照常在 MiniMax Code 对话，插件展示原生 `task` 子 Agent 何时启动、执行了哪些工具、最终回复了什么，以及结果是否出现在父会话。插件不创建或控制 Agent。

时间线使用任务实际起止时间，并对同一轮委派的任务标出运行区间是否重叠及结果在当前父会话历史中的匹配情况。父 Agent 同一条消息中提出两个任务，不代表两者并行。任务记录中的“已交付”不等于父会话历史已核实回传；历史被压缩或无法读取时会标为暂无法核实。即使匹配成功，也不表示父 Agent 已理解、采用或验证结果。

## 安装与使用

需要 MiniMax Code 3.1.4 或更高版本。

将整个目录（含 `.minimax-plugin/`）复制到 `~/.minimax/plugins/agent-flow/`，重启 MiniMax Code，然后说“打开 Agent 协作透视”。MiniApp 标签页附属于打开它的会话；在别的会话打开后，仍可在页面内选择之前的会话。宿主没有向插件提供当前聊天的 ID，因此页面**推断**最近更新的本机会话并自动跟随，包括尚无子任务的新会话；手动选择会话后保持选择，点击“跟随最新会话”可恢复自动跟随。页面打开时每三秒刷新任务、每十五秒刷新会话列表，关闭后不运行后台监控。

点击子任务可查看父 Agent 发出的 `task` 指令、子 Agent 最终回复与工具名称。这些内容是记录中的陈述和操作，不能单独证明代码修改正确。若旧消息已被压缩移出活动历史，详情可能缺失，但持久化的任务与父子关系仍可见。会话列表先显示 40 条，需要时可点“加载更多会话”。

首版只覆盖原生 `task` 子 Agent，不覆盖 MiniMax Bot 群聊、MoMo 自管任务、云端会话或任意插件自建 Agent 会话。

## Tested environment

- MiniMax Code 3.1.4 / macOS：已用一条含两个前台 `explore` 子 Agent 的真实本机会话验证任务、子会话、父会话结果可以关联；插件已显示在“插件·技能”列表，用户在桌面端打开页面并确认显示两项子任务。
- Node.js 24.21.0：合成测试覆盖旧会话、错误路径、父会话回传缺失以及嵌套的失败后台任务；已运行仓库检查。
- 使用 Node 跨平台路径 API；Windows 尚未实测。

## Data & access

- 只读打开 `~/.minimax/v2/sqlite/runtime-state.sqlite`，并读取 `~/.minimax/v2/sessions` 中所选会话的 `messages.jsonl`；读取前核对历史目录编码的会话 ID，拒绝符号链接路径，运行期间缓存未变化的历史文件。设置 `MAVIS_HOME` 时以该目录为根。
- MiniApp 宿主没有提供观察其他普通会话的稳定 API。以上路径和结构是 MiniMax Code 3.1.4 中观察到的**未承诺稳定的内部格式**；版本变化可能导致读取失败。关联不一致时显示错误或警告，不猜测关系。
- 不写入宿主文件、插件数据或浏览器存储；不向外联网、不启动进程或 Agent、不提供 MCP，也不在页面关闭后继续监控。
- 文本只送到本机 MiniApp 页面，并按纯文本渲染。

## 开发

在仓库根目录运行 `node --test plugins/huixin615/agent-flow/tests/*.test.mjs` 和 `npm run check`。合成测试不包含真实会话内容。
